## คำชี้แจงก่อนอ่าน

เอกสารนี้เป็น **เอกสารที่ปรึกษาภายใน (Internal Advisory Document)** ซึ่งจงใจเขียนแบบปฏิปักษ์ (Adversarial by Design) เพื่อเปิดจุดอ่อนที่การอ่านแบบปกติจะมองข้าม ประโยคที่รุนแรงในเอกสารนี้เป็น **เครื่องมือทางระเบียบวิธี (Methodological Instrument)** ไม่ใช่การกล่าวหาว่าผู้เขียนเปเปอร์จงใจผิดจริยธรรม

ข้อกำหนดการอ่านสามประการ

1. ทุกข้อกล่าวหาต้องอ่านคู่กับ **หลักฐาน** ที่ระบุไว้ และต้องตรวจสอบซ้ำได้ด้วยเครื่องมือ (Python หรือโค้ดโจมตี)
2. ข้อใดที่เปเปอร์ทำถูกต้อง ผู้วิจารณ์ยอมรับไว้อย่างชัดเจนในหัวข้อ 3.3 เพื่อไม่ให้เกิดอคติจากการเลือกหลักฐาน (Cherry-Picking)
3. ไม่มีการค้นพบงานตีพิมพ์ที่เจาะจงว่าทำลายระบบเข้ารหัสคอลลัทซ์โดยเฉพาะ การโจมตีในหัวข้อ 5 จึงเป็น **การโจมตีที่ผู้วิจารณ์สร้างขึ้นจากคลาสการโจมตีมาตรฐาน (Standard Attack Classes)** และต้องยืนยันด้วยการรันจริงก่อนนำไปอ้างอิงในรายงานสัมมนา

## 1. คำตัดสินโดยสรุป (Executive Verdict)

### 1.1 คำตัดสินหลัก

ตามมาตรฐานของวิทยาการรหัสลับสมัยใหม่ (Modern Cryptography) ระบบของ Ballesteros และคณะ ปี 2018 **ไม่ใช่ระบบเข้ารหัส (Cipher) ในความหมายทางวิศวกรรม** แต่เป็น **รหัสแทนที่เชิงเดี่ยวแบบพึ่งกุญแจ (Key-Dependent Monoalphabetic Substitution)** ที่ห่อด้วยรหัสความยาวแปรผัน (Variable-Length Code) และสลับตำแหน่งแบบตายตัว (Fixed Transposition)

ผลลัพธ์ที่ตามมา

- **ข้อความต้นฉบับที่รู้หนึ่งภาพ (One Known Plaintext) เพียงพอต่อการกู้กุญแจสมมูลทั้งชุด (Full Equivalent Key Recovery)** และถอดรหัสภาพอื่นทุกภาพที่ใช้กุญแจเดียวกันได้ภายในเวลาไม่ถึงหนึ่งวินาที
- การอ้าง **ความลับสมบูรณ์ (Perfect Secrecy)** ตามทฤษฎีของแชนนอน **ไม่เป็นความจริง** โดยอาศัยการนับขนาดปริภูมิข้อความผิดพลาด
- ปริภูมิกุญแจที่อ้าง $256! \approx 8.57 \times 10^{506}$ **ไม่ใช่ปริภูมิกุญแจที่แท้จริง** แต่เป็นจำนวนการเรียงสับเปลี่ยนของรหัสคอลลัทซ์ 256 แบบ ซึ่งเมื่อพิจารณาเมล็ดกุญแจ (Seed) ที่ผู้ใช้พิมพ์จริงแล้ว ปริภูมิจะยุบตัวลงอย่างรุนแรง
- คอขวดเชิงปฏิบัติที่สำคัญที่สุดคือ **การขยายขนาดข้อมูลประมาณ 6 เท่า** และ **ความเสียหายจากตัวแปลงรหัสเสียง (Audio Codec Corruption)** ซึ่งขัดแย้งกับช่องทางส่งข้อมูลที่เปเปอร์เสนอเอง

### 1.3 คำตัดสินบรรทัดเดียว

หัวข้อนี้ **ยังใช้เป็นหัวข้อสัมมนาได้ และควรใช้** แต่ต้อง **พลิกกรอบจาก "สร้างระบบเข้ารหัสที่ปลอดภัย" เป็น "ทำลายระบบเข้ารหัสที่อ้างว่าปลอดภัย" (From Build to Break)** เพราะเปเปอร์นี้เป็นกรณีศึกษาที่สมบูรณ์แบบของความผิดพลาดเชิงระเบียบวิธีที่พบบ่อยที่สุดในสาขา ซึ่งให้คุณค่าทางการศึกษาสูงกว่าการทำซ้ำผลลัพธ์ที่ผิดเสียอีก

## 2. ขอบเขต ระเบียบวิธี และข้อจำกัดของการวิจารณ์

### 2.1 สิ่งที่ตรวจสอบ

1. อ่านข้อความเต็มของ Ballesteros และคณะ 2018 จากไฟล์ PDF โดยตรง (856 บรรทัดที่สกัดได้)
2. อ่านข้อความเต็มของ Al-Hyari และคณะ 2024 โดยมีการทำ OCR ตารางภาพ (Raster Table) ที่ไม่มีชั้นข้อความ (Text Layer)
3. คำนวณเชิงจำนวนเต็ม (Integer Arithmetic) ด้วย Python สำหรับสถิติของรหัสคอลลัทซ์ ขนาดปริภูมิ และปัจจัยการขยายข้อมูล
4. ตรวจสอบการมีอยู่จริงของงานอ้างอิงรหัสลับทุกชิ้นผ่านการค้นเว็บ เพื่อป้องกันการอ้างอิงที่กุขึ้น (Fabricated Citation)
5. ตรวจสอบเอกสารภายในสามฉบับในโฟลเดอร์นี้เพื่อหาความไม่สอดคล้องกับข้อเท็จจริงของเปเปอร์

### 2.2 ข้อจำกัดของการวิจารณ์

1. **ไม่ได้รันโค้ดโจมตีจริง** ข้อเสนอการโจมตีในหัวข้อ 5 เป็นการวิเคราะห์เชิงทฤษฎีจากโครงสร้างของขั้นตอนวิธี ยังไม่ได้ยืนยันด้วยการลงมือปฏิบัติ
2. **ตัวเลขของ Al-Hyari และคณะ 2024 ส่วนหนึ่งมาจาก OCR** เนื่องจากตารางในไฟล์ PDF เป็นภาพ ตัวเลขที่ใช้ตัดสินใจเชิงวิกฤตต้องตรวจซ้ำกับไฟล์ต้นฉบับ
3. **ไม่มีงานตีพิมพ์ที่ทำลายระบบเข้ารหัสคอลลัทซ์โดยตรง** การโจมตีที่เสนอจึงเป็นการประยุกต์คลาสการโจมตีมาตรฐานของระบบสับเปลี่ยนและแพร่กระจาย (Permutation-Diffusion)
4. **ไม่มีข้อมูลรหัสต้นฉบับของผู้เขียน** การวิเคราะห์จึงอิงจากคำบรรยายในเปเปอร์ ซึ่งในบางจุดไม่สมบูรณ์เพียงพอต่อการทำซ้ำ (ดูหัวข้อ 6.4)

### 2.3 หลักเกณฑ์เชิงบรรทัดฐานที่ใช้ตัดสิน (Normative Criteria)

ระบบเข้ารหัสที่อ้างว่าปลอดภัยต้องผ่านอย่างน้อยสามด่าน ซึ่งเปเปอร์ทั้งสองฉบับไม่ผ่านด่านใดเลย

1. **แบบจำลองผู้โจมตี (Adversary Model)** ต้องระบุชัดว่าป้องกันการโจมตีแบบใด รวมถึงการโจมตีแบบเลือกข้อความต้นฉบับ (Chosen-Plaintext Attack, CPA) และแบบรู้ข้อความต้นฉบับ (Known-Plaintext Attack, KPA)
2. **การพิสูจน์ความปลอดภัยเชิงรูปแบบ (Formal Security Proof)** ต้องมีการลดทอน (Reduction) ไปสู่ปัญหาที่ยาก เช่น การพิสูจน์ความเป็น IND-CPA
3. **การแยกแยะจากสัญญาณสุ่ม (Pseudorandomness)** ต้องไม่มีความไม่แปรเปลี่ยน (Invariant) ที่ผู้โจมตีใช้แยกแยะได้

ตัวชี้วัดทางสถิติอย่าง NPCR, UACI, เอนโทรปี และสหสัมพันธ์ **ไม่ใช่หลักฐานความปลอดภัย** แต่เป็นเพียงสัญญาณจำเป็น (Necessary Condition) ที่ระบบที่พังแล้วก็ยังผ่านได้ (ดูหัวข้อ 7.3 และ 8.1 เส้นทางที่ 7)

## 3. การสร้างแบบจำลองสิ่งที่เปเปอร์ทำจริง (Faithful Reconstruction)

### 3.1 เส้นทาง Ballesteros และคณะ 2018

**ขั้นตอนการเข้ารหัส (Image Coding)**

1. สร้างชุดรหัสคอลลัทซ์ (Collatz Code) สำหรับจำนวนเต็ม 1 ถึง 256 โดยให้ $x$ แต่ละค่าได้รหัสความยาวแปรผัน
   $$T(x)=\begin{cases} x/2 & \text{ถ้า } x \text{ เป็นจำนวนคู่} \\ 3x+1 & \text{ถ้า } x \text{ เป็นจำนวนคี่} \end{cases}$$
   บันทึก 1 บิตต่อหนึ่งรอบ (1 ถ้าป้อนจำนวนคี่, 0 ถ้าป้อนจำนวนคู่) แล้วเติมหัวรหัส (Header) `11` ไว้ข้างหน้า

2. เพิ่มค่าพิกเซลขึ้นหนึ่ง เพื่อย้ายช่วง $[0,255]$ ไปเป็น $[1,256]$
3. สลับลำดับแถวของชุดรหัสทั้ง 256 แถว ตาม **เมล็ดกุญแจ (Seed)** ที่ผู้ใช้เลือก ได้ชุดที่เปเปอร์เรียกว่า DCC
4. กวาดพิกเซลจากซ้ายไปขวา บนลงล่าง แทนค่าพิกเซล $p$ ด้วยรหัสของแถว $p+1$ ของ DCC แล้วต่อรหัสเข้าด้วยกัน โดยพิกเซลลำดับที่หนึ่งต่อไว้ข้างหน้า พิกเซลลำดับที่สองต่อไว้ข้างหลัง สลับกันไป
5. ตัดสายบิตเป็นคำขนาด 16 บิต แปลงเป็นค่าทศนิยมในช่วง $[-1,1]$ แล้วบันทึกเป็นไฟล์เสียง WAV

**กุญแจ (Key)** ประกอบด้วยเมล็ดกุญแจ และขนาดภาพ $m \times n$

**ช่องทางส่งข้อมูลที่เปเปอร์เสนอ** ส่งไฟล์เสียงที่เข้ารหัสแล้วผ่าน WhatsApp และส่งกุญแจผ่านอีเมล

### 3.2 ระบบนามธรรมที่แท้จริงของ Ballesteros (The Real Abstract Cipher)

ให้ $W=\{w_0, w_1, \ldots, w_{255}\}$ เป็นเซตของรหัสคอลลัทซ์ 256 แบบ ซึ่งเป็น **ข้อมูลสาธารณะ** ที่ใครก็คำนวณได้ และให้ $\sigma_k$ เป็นการเรียงสับเปลี่ยนของ $W$ ที่กำหนดโดยเมล็ดกุญแจ $k$

$$\text{Ciphertext} = \mathrm{concat}\big(\sigma_k(v_{\pi(1)}),\ \sigma_k(v_{\pi(2)}),\ \ldots,\ \sigma_k(v_{\pi(L)})\big)$$

โดย $v_i$ คือค่าพิกเซลที่ตำแหน่ง $i$, $L=mn$ และ $\pi$ คือการสลับตำแหน่งแบบคงที่ (ไม่ขึ้นกับกุญแจ)

เพราะ $\pi$ คงที่และ $\sigma_k$ เป็นการแทนที่สัญลักษณ์ ระบบนี้จึงสมมูลกับ

$$C \;=\; \mathrm{Sub}_{\sigma_k}\big(\mathrm{Perm}_{\pi}(P)\big)$$

กล่าวคือ **รหัสแทนที่เชิงเดี่ยว (Monoalphabetic Substitution) บนตัวอักษรขนาด 256 ตัว ประกอบกับการสลับตำแหน่งที่ไม่ใช่ความลับ** ซึ่งเป็นรหัสที่ถูกทำลายได้ด้วยการวิเคราะห์ความถี่มาตั้งแต่ยุคก่อนคอมพิวเตอร์

### 3.3 จุดที่เปเปอร์ทำได้ถูกต้อง (Required Concessions)

การวิจารณ์แบบปฏิปักษ์ต้องยอมรับจุดที่ถูกต้อง มิฉะนั้นจะกลายเป็นการกล่าวอ้างลอย ๆ

1. **การพิสูจน์ว่าหัวรหัส `11` ไม่ปรากฏในเนื้อรหัสถูกต้อง** เพราะจำนวนคี่บวกหนึ่งแล้วได้จำนวนคู่เสมอ ลำดับ "คี่-คี่" จึงเป็นไปไม่ได้ ทำให้การตัดคำ (Framing) ทำได้โดยไม่กำกวม
2. **การแปลงค่าพิกเซลเป็นรหัสเป็นแบบหนึ่งต่อหนึ่งจริง** ผู้วิจารณ์ตรวจสอบด้วย Python แล้วว่าสายบิตภาวะคู่คี่ (Parity String) ของค่าตั้งแต่ 1 ถึง 256 **แตกต่างกันทั้ง 256 แบบ** จึงไม่มีการชนกัน (Collision) และการถอดรหัสมีนิยามชัดเจน
3. **แนวคิดการแทนที่ด้วยรหัสความยาวแปรผันเป็นแนวคิดที่สร้างสรรค์** และการรวมขั้นตอนสับสน (Confusion) กับขั้นตอนแพร่กระจาย (Diffusion) เข้าเป็นรหัสชุดเดียวเป็นมุมมองที่แตกต่างจากงานร่วมสมัย
4. **การทดสอบความไวต่อกุญแจ (Key Sensitivity) ในระดับการรับรู้ผ่านจริง** การเปลี่ยนตัวพิมพ์ของคำว่า Shannon เป็น shannon ทำให้ภาพที่ถอดได้เสียหายจริง ข้อนี้เป็นข้อเท็จจริง
5. **ผู้เขียนระบุจุดอ่อนของตนเองในงานอนาคตไว้อย่างซื่อสัตย์** หัวข้อ 7 ของเปเปอร์ระบุว่าต้องหาจุดอ่อนเรื่องความน่าจะเป็นของปริภูมิรหัส และต้องเพิ่มการสลับบิตเพื่อยกเอนโทรปี นี่เป็นความซื่อสัตย์ทางวิชาการที่ควรชม

## 4. ข้อบกพร่องทางคณิตศาสตร์ (Mathematical Flaws)

### 4.1 การอ้างความลับสมบูรณ์ขัดกับทฤษฎีบทของแชนนอน

เปเปอร์ระบุสมการที่ (10)

$$|K| = |M| = |C|$$

แล้วสรุปว่า "สอดคล้องกับเงื่อนไขความลับสมบูรณ์ที่นิยามโดยแชนนอน"

**ข้อบกพร่องมีสามชั้น**

ชั้นที่หนึ่ง **เงื่อนไขที่ยกมาไม่ใช่เงื่อนไขของความลับสมบูรณ์** Shannon (1949) นิยามว่าความลับสมบูรณ์หมายถึง $H(M \mid C) = H(M)$ กล่าวคือสำหรับข้อความ $m$ ใด ๆ ที่มีความน่าจะเป็นเป็นบวก

$$\Pr[M=m \mid C=c] = \Pr[M=m]$$

ซึ่งสมมูลกับเงื่อนไขว่า **จำนวนกุญแจที่ส่งข้อความ $m$ ไปเป็นข้อความเข้ารหัส $c$ ต้องเท่ากันทุกคู่ $(m,c)$** การมี $|K| \ge |M|$ เป็นเพียงเงื่อนไขพอเพียงในกรณีพิเศษที่กุญแจสุ่มสม่ำเสมอและ **ใช้เพียงครั้งเดียว** เท่านั้น

ชั้นที่สอง **ภาพที่ 8 ในเปเปอร์แสดงโครงสร้างตรงกันข้ามกับความลับสมบูรณ์** แผนภาพเส้นเชื่อมแสดง $m_1$ ต่อกับ $c_1$ ผ่าน $k_1$, $m_2$ ต่อกับ $c_2$ ผ่าน $k_2$ ไปเรื่อย ๆ ซึ่งเป็นโครงสร้างแบบหนึ่งต่อหนึ่ง (Deterministic Bijection) ในระบบที่มีความลับสมบูรณ์จริง ทุกข้อความต้องต่อกับทุกข้อความเข้ารหัสได้ เส้นเชื่อมจะต้องเต็มระนาบ ไม่ใช่เส้นทแยง

ชั้นที่สาม **การใช้งานจริงละเมิดเงื่อนไขหนึ่งครั้งต่อหนึ่งกุญแจ** เปเปอร์ใช้กุญแจห้าตัวต่อภาพหนึ่งภาพ รวม 20 ภาพ เป็น 100 ไฟล์เสียง และส่งกุญแจซ้ำผ่านอีเมล ความลับสมบูรณ์ที่ต้องใช้กุญแจครั้งเดียวจึงพังทันที

### 4.2 การนับขนาดปริภูมิข้อความและปริภูมิข้อความเข้ารหัสผิด

เปเปอร์อ้างว่าในแผนภาพเส้นของแชนนอน ฝั่งซ้าย (ข้อความ) มีวงกลม $256!$ วง เพราะภาพมี 256 ค่าระดับสี และฝั่งขวา (ข้อความเข้ารหัส) มี $256!$ วง เพราะระบบมีรหัสคอลลัทซ์ 256 แบบ

**นี่เป็นข้อผิดพลาดเชิงแนวคิดพื้นฐาน**

- ปริภูมิข้อความ (Message Space) ของภาพขนาด $m \times n$ ที่มี 8 บิตต่อพิกเซล คือ $|M| = 256^{mn}$ ไม่ใช่ $256!$ ภาพขนาด $512 \times 512$ มีขนาดปริภูมิเท่ากับ $2^{2\,097\,152}$
- ปริภูมิข้อความเข้ารหัสคือเซตของสายบิตที่ต่อจากรหัส $L$ คำ คือขนาด $256^{L}$ ไม่ใช่ $256!$
- การที่เปเปอร์นำ "จำนวนค่าที่เป็นไปได้ของหนึ่งพิกเซล" มาปนกับ "จำนวนข้อความทั้งหมดที่เป็นไปได้" คือการสลับระดับ (Level Confusion) ระหว่างตัวอักษร (Alphabet) กับข้อความ (Message)

**ผลที่ตามมาในเชิงปริมาณ** ผู้วิจารณ์คำนวณได้ว่า

$$\log_2(256!) = 1684.0 \ \text{บิต} \qquad \text{แต่} \qquad \log_2|M| = 2\,097\,152 \ \text{บิต}$$

ปริภูมิกุญแจที่อ้างจึงเล็กกว่าปริภูมิข้อความประมาณ $2^{-2\,095\,468}$ เท่า สมการที่ (10) เป็นเท็จเชิงตัวเลข ไม่ใช่เพียงเท็จเชิงตรรกะ

**หมายเหตุเพื่อความเป็นธรรม** ตัวเลข $2^{1684}$ เองนั้นใหญ่กว่าปริภูมิกุญแจของ AES-256 ที่ $2^{256}$ เสียอีก ดังนั้นนักอ่านผิวเผินจะรู้สึกว่าปริภูมิกุญแจ "มากพอ" ประเด็นของผู้วิจารณ์คือ **แกนที่ใช้วัดผิดทั้งหมด** เพราะขนาดปริภูมิกุญแจไม่เคยเป็นตัวชี้วัดความปลอดภัย เมื่อมีการโจมตีที่ข้ามการค้นแบบถึกไปได้ทั้งหมด

### 4.3 ข้อขัดแย้งภายในเรื่องจำนวนรอบของรหัสคอลลัทซ์

เปเปอร์บรรยายตัวอย่างในหัวข้อ 2.1 ว่า

> "สำหรับตัวอย่างนี้ ต้องใช้ 5 รอบในการลดจำนวน 3 ลงเหลือ 1"

แต่สายวงโคจรจริงคือ $3 \to 10 \to 5 \to 16 \to 8 \to 4 \to 2 \to 1$ ซึ่งใช้ **7 รอบ** (หรือ 8 พจน์) และหัวข้อ 3 ระบุเองว่าความยาวรหัสของ 3 คือ 10 บิต ซึ่งสอดคล้องกับ 8 พจน์บวกหัวรหัส 2 บิต ไม่ใช่ 5 รอบบวกหัวรหัส

ในทำนองเดียวกัน หัวข้อ 3 ระบุว่าค่า 4 ต้องใช้ "สามรอบ" และความยาวรหัสเท่ากับ 5 แต่ $4 \to 2 \to 1$ ใช้เพียง 2 รอบ (3 พจน์)

ผู้วิจารณ์ตรวจสอบด้วย Python สำหรับค่าทั้งหมด 1 ถึง 256 ได้ข้อเท็จจริงดังนี้

| ตัวชี้วัด | ค่าที่คำนวณได้ |
|:---|:---|
| จำนวนรอบเฉลี่ย (สำหรับ 1 ถึง 256) | 44.98 |
| จำนวนรอบสูงสุดในช่วงนี้ | 127 |
| ความยาวรหัสเฉลี่ย (พจน์ + 2) | 47.98 บิต |
| ค่าที่มีภาวะคู่คี่ซ้ำกัน | 0 จาก 256 |

**ข้อบกพร่องคือเปเปอร์ใช้คำว่า "รอบ" (Iteration) กับ "พจน์" (Term) สลับกันโดยไม่นิยาม** ทำให้ขั้นตอนวิธีไม่สามารถทำซ้ำได้ตรงตามคำบรรยาย (ดูหัวข้อ 6.4) ข้อเท็จจริงนี้ไม่ได้ทำลายความถูกต้องของระบบ แต่ทำลายความน่าเชื่อถือของบทความในฐานะเอกสารอ้างอิงทางวิศวกรรม

### 4.4 สถิติที่เปเปอร์รายงานเองไม่ผ่านเกณฑ์ที่เปเปอร์อ้าง

**ก. เอนโทรปี**

บทคัดย่ออ้างว่า "ค่าเอนโทรปีและระดับความไม่เป็นระเบียบของสัญญาณเสียงที่เข้ารหัสแล้วใกล้ค่าสูงสุดของความสุ่มมาก" แต่ข้อมูลจริงในหัวข้อ 5.4 ระบุว่าเอนโทรปี **สูงกว่า 13 และประมาณ 14** จากค่าสูงสุด 16 บิต

- คิดเป็นร้อยละ 81 ถึง 87.5 ของค่าสูงสุด ซึ่งไม่ใช่ "ใกล้ค่าสูงสุด"
- ตารางที่ 1 ของเปเปอร์เองรายงานค่า Relative Entropy ของตนไว้ที่ **ร้อยละ 87.5** ขณะที่วิธีเปรียบเทียบอยู่ที่ร้อยละ 99.7 ถึง 99.9 เปเปอร์จึงมีเอนโทรปีต่ำกว่าคู่เทียบทุกตัว
- ตามทฤษฎีบทการเข้ารหัสแหล่งข้อมูล (Source Coding Theorem) ความซ้ำซ้อนนี้ **บีบอัดได้จริง** ผู้วิจารณ์ประมาณการว่าสำหรับภาพขนาด $512 \times 512$ จะได้จำนวนตัวอย่างเสียงประมาณ $786\,112$ ตัวอย่าง ความซ้ำซ้อนประมาณ 2 บิตต่อตัวอย่าง รวมประมาณ 1.57 ล้านบิต หรือประมาณ 196 กิโลไบต์ของโครงสร้างที่บีบอัดได้
- สัญญาณรหัสลับที่สุ่มจริงต้องบีบอัดไม่ได้ ข้อเท็จจริงว่าบีบอัดได้จึงเป็นข้อโต้แย้งเชิงทฤษฎีว่า **สายบิตไม่ใช่สัญญาณสุ่มเชิงรหัสลับ**

**ข. ค่า DS (Disorder Scrambling)**

เปเปอร์ระบุว่าค่าสูงสุดคือ 2 และ "สัญญาณที่เข้ารหัสใกล้ค่าสูงสุด" แต่ข้อมูลคือทุกค่าสูงกว่า 0.8 และส่วนใหญ่ใกล้ 1.2

- คิดเป็นร้อยละ 40 ถึง 70 ของค่าสูงสุด ไม่ใช่ "ใกล้ค่าสูงสุด"
- การนำค่า DS ไปเทียบกับงานอ้างอิงที่ได้ 0.6 (อ้างอิงที่ 28) **ไม่ชอบด้วยวิธีวิทยา** เพราะงานอ้างอิงนั้นเป็นระบบสลับเสียงคนละสูตร (Different Definition) การเทียบตัวเลขที่นิยามต่างกันไม่ได้แปลว่าดีกว่า

**ค. ค่า UACI และการตีความทิศทางผิด**

เปเปอร์คำนวณ UACI จากสายบิต $bs$ โดยใช้สมการที่ (11)

$$\mathrm{UACI} = \frac{\sum |C_1 - C_2|}{L} \times 100$$

โดยหารด้วย $L$ ซึ่งเป็นจำนวนบิต ไม่ใช่หารด้วย $255L$ ตามนิยามมาตรฐานบนภาพ 8 บิต และรายงานค่าอยู่ที่ 0.44 ถึง 0.46

- เปเปอร์อ้างว่า "ยิ่ง UACI สูงยิ่งแข็งแกร่ง" ซึ่งไม่ถูกต้อง ค่า UACI มี **ค่าอุดมคติ** อยู่ที่ประมาณร้อยละ 33.4635 สำหรับภาพ 8 บิต ค่าที่สูงเกินไปบ่งชี้ความลำเอียง (Bias) ไม่ใช่ความแข็งแกร่ง
- เปเปอร์สรุปในหัวข้อ 6 ว่า "จุดได้เปรียบหลักอยู่ที่ค่า UACI ในการต้านการโจมตีเชิงผลต่าง" ซึ่งเป็นการอนุมานจากตัวเลขที่ตีความผิด

**ง. ตัวชี้วัดที่หายไปทั้งหมด**

เปเปอร์ 2018 **ไม่รายงาน** ค่าต่อไปนี้เลย ซึ่งเป็นตัวชี้วัดมาตรฐานที่บทความรหัสภาพต้องมี

- NPCR (Number of Pixels Change Rate) ซึ่งเป็นคู่หูของ UACI และงานร่วมสมัยทุกรายรายงาน
- การทดสอบไคสแควร์ของฮิสโตแกรม (Chi-Square Histogram Test)
- ชุดทดสอบ NIST SP 800-22
- การทดสอบความไวต่อกุญแจเชิงปริมาณ (MSE, PSNR หรืออัตราบิตที่ผิด)
- การทดสอบความทนทานต่อสัญญาณรบกวน (Noise Robustness)

### 4.5 การเปรียบเทียบข้ามหน่วยในตารางที่ 1 (Apples-to-Oranges Comparison)

ตารางที่ 1 เปรียบเทียบงานของเปเปอร์กับวิธีอื่นโดยวางค่า UACI ของตนที่ 0.44 ไว้ข้างค่าของวิธีอื่นที่ 0.33

ข้อบกพร่องคือ **ค่า 0.44 คำนวณจากสายบิต** (หน่วยบิต) แต่ค่า 0.33 ของวิธีอื่นคำนวณจาก **ความเข้มพิกเซล 8 บิต** (หน่วยระดับความเข้ม) ตัวเลขสองชุดอยู่ในหน่วยที่ต่างกันโดยสิ้นเชิง การนำมาเข้าตารางเดียวกันจึงเป็นการเปรียบเทียบที่ผิดวิธี

นอกจากนี้ค่า Relative Entropy ร้อยละ 87.5 ของเปเปอร์ต่ำกว่าทุกแถวในตารางเดียวกัน และเปเปอร์ก็ยอมรับในบทสรุปว่าต้องปรับปรุง แต่นำเสนอตารางในลักษณะที่อ่านได้ราวกับตนชนะทุกคอลัมน์

### 4.6 ข้อบกพร่องทางคณิตศาสตร์ใน Al-Hyari และคณะ 2024

**ก. ขนาดปริภูมิกุญแจขัดแย้งในตัวเอง**

เปเปอร์ระบุสมการว่าการค้นแบบถึก (Brute Search) มีขนาด

$$(|t| \times |p|)^3 = (9\times10^{6} \times 620)^3 \approx 1.737 \times 10^{29}$$

แล้วเขียนว่า "มากกว่า $2^{97}$ เล็กน้อย" และ **ในบรรทัดถัดมา** เขียนว่า "พื้นที่ค้นหาสำหรับการโจมตีแบบถึกอยู่ต่ำกว่า $2^{100}$ เล็กน้อย"

ตรวจสอบได้ว่า $\log_2(1.737\times10^{29}) \approx 97.14$ บิต ดังนั้นคำว่า "ต่ำกว่า $2^{100}$ เล็กน้อย" นั้น **ผิดอยู่ประมาณ $2^{2.9} \approx 7.6$ เท่า**

ปัญหาที่ร้ายแรงกว่าคือ **กุญแจจริงคือเลขทศนิยม 15 หลัก** จำนวนกุญแจที่แตกต่างกันทั้งหมดจึงไม่เกิน

$$10^{15} \approx 2^{49.8}$$

การนับ $(|t| \times |p|)^3$ เป็นการนับจำนวนวิธีแบ่งพาร์ทิชัน ซึ่งไม่ใช่จำนวนกุญแจที่แตกต่างกัน เปเปอร์เองยังระบุว่า "เราต้องการเพียง 64 บิต" อีกด้วย ตัวเลข $2^{97}$ จึงเป็นการพองปริภูมิกุญแจ (Key Space Inflation) ประมาณ $2^{47}$ เท่า

**ข. ค่า UACI กระจัดกระจายและมีค่าที่เป็นสัญญาณเตือน**

เปเปอร์รายงานค่า UACI อยู่ในช่วงกว้าง 0.2849 ถึง 0.4009 และสำหรับภาพดำสนิทและขาวสนิทได้ค่า 0.4987 และ 0.4948

- ช่วงที่กว้างเช่นนี้เองบ่งชี้ว่าระบบไม่เสถียร และค่าต่ำสุด 0.2849 ต่ำกว่าค่าอุดมคติ 0.3346 อย่างมีนัยสำคัญ
- ค่าเกือบ 0.5 สำหรับภาพสีเดียวเป็นสัญญาณเตือน (Red Flag) ว่าขั้นตอนแพร่กระจายมีอคติรุนแรงต่อภาพที่มีฮิสโตแกรมเอกฐาน (Degenerate Histogram) ซึ่งเปเปอร์ไม่ได้ตั้งข้อสังเกตหรืออภิปรายเลย

**ค. เอนโทรปีต่ำกว่าคู่เทียบทุกตัวแต่ยังอ้างความเหนือกว่า**

เปเปอร์รายงานค่าเฉลี่ยเอนโทรปีของภาพเข้ารหัสที่ 7.8879 ขณะที่ตารางเปรียบเทียบของเปเปอร์เองแสดงคู่เทียบที่ 7.9893, 7.9974, 7.9976 และ 7.9973

คำนวณความซ้ำซ้อนต่อพิกเซลได้ $8 - 7.8879 = 0.1121$ บิต สำหรับภาพขนาด $512 \times 768 \times 3$ ซึ่งมี $1\,179\,648$ พิกเซล ความซ้ำซ้อนรวมประมาณ 132,238 บิต หรือประมาณ 16.5 กิโลไบต์ของโครงสร้างที่บีบอัดได้

## 5. ช่องโหว่ทางวิทยาการรหัสลับ (Cryptographic Vulnerabilities)

### 5.1 ไม่มีตัวสร้างเลขสุ่มเชิงรหัสลับ และไม่มีกระแสกุญแจ (No CSPRNG, No Keystream)

ระบบของ Ballesteros **ไม่มีกระแสกุญแจ (Keystream) เลย** ความปลอดภัยทั้งหมดขึ้นอยู่กับความลับของการเรียงสับเปลี่ยน $\sigma_k$ เพียงอย่างเดียว ในเชิงวิทยาการรหัสลับนี่คือ **สมมติฐานความปลอดภัยโดยการปิดบัง (Security Through Obscurity) ในระดับโครงสร้าง** เพราะหากผู้โจมตีรู้ขั้นตอนวิธี ซึ่งต้องถือว่ารู้ตามหลักของ Kerckhoffs แล้ว ความลับที่เหลือคือเพียงการเรียงสับเปลี่ยนของชุดโค้ดสาธารณะ

ไม่มีหลักฐานหรือข้อโต้แย้งใดในเปเปอร์ว่ารหัสคอลลัทซ์มีสมบัติของตัวสร้างเลขสุ่มเทียมเชิงรหัสลับ (Cryptographically Secure Pseudorandom Number Generator, CSPRNG) ได้แก่ การไม่ทำนายอนาคตได้ (Unpredictability) และการต้านการแยกแยะ (Indistinguishability) สมมติฐานคอลลัทซ์เป็นข้อความคาดการณ์ทางคณิตศาสตร์ (Conjecture) ที่ยังไม่ได้รับการพิสูจน์ ซึ่งไม่มีความหมายเชิงรหัสลับแม้แต่ประการเดียว การที่ผู้เขียนนำมาใช้บ่อยครั้งในฐานะ "ความโกลาหล" (Chaos) เป็นการยืมความน่าเกรงขามทางคณิตศาสตร์มาใช้โดยไม่มีเหตุผลรองรับ

### 5.2 การโจมตีแบบเลือกข้อความต้นฉบับ (Chosen-Plaintext Attack): ภาพเดียวก็เพียงพอ

**ขั้นตอนการโจมตี (Attack Construction)**

1. สร้างภาพทดสอบขนาด $256 \times 256$ ที่พิกเซลตำแหน่ง $(i,j)$ มีค่าเท่ากับ $j$ กล่าวคือแถวที่ $j$ มีค่าคงที่ทั้งแถว (หรือสร้างภาพที่มีค่าระดับสีครบทั้ง 256 ค่า วางตามตำแหน่งที่รู้)
2. ส่งภาพนี้ให้ระบบเข้ารหัสด้วยกุญแจเป้าหมาย ได้ไฟล์เสียงที่เข้ารหัส
3. ตัดสายบิตเป็นคำโดยหาตำแหน่งหัวรหัส `11` และอ่านความยาวของแต่ละคำ
4. เพราะรู้ค่าพิกเซลของภาพทดสอบทุกตำแหน่ง และรู้กฎการวางตำแหน่งแบบตายตัว จึงจับคู่คำแต่ละคำเข้ากับค่าพิกเซลได้ทันที
5. ผลลัพธ์คือตาราง $\sigma_k$ ครบทั้ง 256 รายการ ซึ่งเป็น **กุญแจสมมูล (Equivalent Key)**
6. นำ $\sigma_k$ ไปถอดรหัสภาพอื่นทุกภาพที่ใช้กุญแจเดียวกัน

**ข้อสังเกตสำคัญ** ผู้โจมตีไม่จำเป็นต้องรู้เมล็ดกุญแจ และไม่ต้องทำการค้นแบบถึกเลย ความซับซ้อนของเวลาเป็นเพียง $O(mn)$ คือการอ่านข้อมูลหนึ่งรอบ

**กรณีที่ง่ายที่สุด** หากสร้างภาพทดสอบที่ทุกพิกเซลมีค่าเดียวกัน สายบิตที่ได้จะเป็นรหัสคำเดียวซ้ำกันทั้งภาพ ทำให้อ่านค่า $\sigma_k(v)$ ได้โดยตรงด้วยตาเปล่า ทำซ้ำ 256 ครั้งก็ได้ตารางครบ ตัวเลข "ภาพทดสอบ 3 ถึง 4 ภาพ" ที่มักอ้างกันในงานตระกูลนี้เป็นค่าที่อนุรักษนิยมเกินไปสำหรับระบบรหัสแทนที่เต็มตัวอักษร เพราะระบบนี้เปิดเผยกุญแจสมมูลทั้งตารางด้วยภาพเดียว

### 5.3 การโจมตีแบบรู้ข้อความต้นฉบับ (Known-Plaintext Attack): ภาพธรรมชาติเพียงหนึ่งภาพ

**นี่คือช่องโหว่ที่ร้ายแรงที่สุดในเชิงปฏิบัติ** เพราะไม่ต้องใช้ภาพที่เลือกเองด้วยซ้ำ

- ภาพถ่ายธรรมชาติหรือภาพสแกนเอกสารเกือบทั้งหมด **มีค่าระดับสีครบทั้ง 256 ค่า** อยู่ในตัว หากมีภาพธรรมดาหนึ่งภาพที่รู้เนื้อหา (เช่น ภาพที่ผู้ใช้อัปโหลดสาธารณะ หรือภาพต้นแบบที่รู้จัก) ผู้โจมตีก็ได้ตาราง $\sigma_k$ ครบ
- ขั้นตอนการโจมตีเหมือนหัวข้อ 5.2 ทุกประการ เพียงแต่เปลี่ยนภาพทดสอบเป็นภาพธรรมชาติที่รู้ค่า

การโจมตีนี้เป็นคลาสเดียวกับที่ Li และ Lo (2011) พิสูจน์เชิงปริมาณสำหรับรหัสที่มีเฉพาะการสลับตำแหน่ง และคลาสเดียวกับที่ Li, Lin, Feng, Lü และ Hao (2018) ใช้ทำลายรหัสที่อ้างว่าปลอดภัยจากตัวชี้วัดเอนโทรปี

### 5.4 การโจมตีแบบมีแต่ข้อความเข้ารหัส (Ciphertext-Only Attack): การวิเคราะห์ความถี่

แม้ผู้โจมตีจะไม่รู้ภาพต้นฉบับเลย ก็ยังทำลายได้ เพราะระบบเป็นรหัสแทนที่เชิงเดี่ยว

ให้ $p(v)$ เป็นฮิสโตแกรมของค่าพิกเซลในภาพธรรมชาติ ซึ่งไม่สม่ำเสมออย่างรุนแรง และให้ $q(w)$ เป็นฮิสโตแกรมของคำที่สังเกตได้ในข้อความเข้ารหัส จะได้

$$q(w) = p\big(\sigma_k^{-1}(w)\big)$$

กล่าวคือ $q$ เป็นเพียงการจัดเรียงใหม่ของ $p$ ผู้โจมตีที่รู้ฮิสโตแกรมโดยประมาณของภาพธรรมชาติประเภทนั้น (ซึ่งรู้ได้จากการเก็บสถิติ) สามารถแก้ปัญหาการจับคู่ (Assignment Problem) เพื่อกู้ $\sigma_k$ ได้ โดยเหลือความกำกวม (Ambiguity) เฉพาะในกลุ่มค่าที่ความถี่เท่ากัน ซึ่งหาได้น้อยมาก

**ช่องทางรั่วเพิ่มเติมจากความยาวรหัส (Length-Channel Leak)** ความยาวของรหัสคอลลัทซ์ $\ell(v)$ เป็นฟังก์ชันที่รู้ได้แบบสาธารณะของค่า $v$ เมื่อผู้โจมตีตัดคำได้ ย่อมสังเกตความยาวของทุกคำได้ทันที ลายนิ้วมือของความยาวนี้ขึ้นอยู่กับฮิสโตแกรมของภาพต้นฉบับเพียงอย่างเดียว จึงเป็นข้อมูลที่รั่วออกมาเสมอ ไม่ว่ากุญแจจะเป็นอะไร

### 5.5 กุญแจสมมูลและการยุบตัวของปริภูมิกุญแจ (Equivalent Key)

ในทฤษฎีการโจมตีระบบรหัสภาพ คำว่า **กุญแจสมมูล (Equivalent Key)** หมายถึงข้อมูลตัวแทนที่ไม่ใช่กุญแจลับจริง แต่ใช้ถอดรหัสได้เหมือนกุญแจลับ

ในกรณีนี้ ผลลัพธ์ของหัวข้อ 5.2 และ 5.3 **คือกุญแจสมมูลเต็มรูปแบบ** ไม่ใช่กุญแจบางส่วน ความซับซ้อนของกุญแจจึงไม่ควรวัดจาก $2^{1684}$ แต่ต้องวัดจาก

$$\text{ความซับซ้อนของกุญแจสมมูล} = O(mn)$$

คือ **เป็นเชิงเส้นต่อขนาดภาพ** ซึ่งในภาษาของวิทยาการรหัสลับหมายความว่ากุญแจถูกทำลายโดยสมบูรณ์ การอ้างขนาดกุญแจ $8.57 \times 10^{506}$ ในบทคัดย่อจึงเป็นการนำเสนอตัวเลขที่ไม่มีความหมายในทางปฏิบัติ

หมายเหตุเพิ่มเติม อาการ **การลู่เข้ากันของกุญแจ (Equivalent Key Collision)** เกิดจากความไม่สม่ำเสมอของขั้นตอนการสร้างเมล็ดกุญแจ การจับคู่เมล็ดกุญแจที่แตกต่างกันไปสู่ตาราง $\sigma_k$ ที่เหมือนกันนั้นทำให้เมล็ดกุญแจที่ใช้ได้จริงมีจำนวนน้อยกว่าจำนวนเมล็ดทั้งหมดอย่างมาก

### 5.6 การใช้กุญแจซ้ำและภาวะขาดนอนซ์ (Key Reuse and No Nonce)

- ตาราง $\sigma_k$ เป็นตัวเดียวกันสำหรับทุกภาพที่ใช้กุญแจเดียวกัน การโจมตีหนึ่งครั้งทำลายข้อมูลทุกชิ้นที่ผ่านกุญแจนั้น
- เปเปอร์ไม่มี **นอนซ์ (Nonce)** หรือ **เวกเตอร์เริ่มต้น (Initialization Vector)** เลย ระบบไม่มีกลไกทำให้ข้อความเข้ารหัสของข้อความเดิมต่างกันในการเข้ารหัสสองครั้ง
- เปเปอร์ระบุอย่างภาคภูมิใจว่า "ข้อมูลเสียงที่เข้ารหัสแตกต่างกันทุกครั้ง และขึ้นอยู่กับกุญแจที่เลือกเท่านั้น" ประโยคนี้เป็นทั้งความจริงและคำสารภาพ เพราะคำว่า "เท่านั้น" คือคำจำกัดความของระบบที่ไม่มีความปลอดภัยเชิงความหมาย (Semantic Security)

### 5.7 การเข้ารหัสเชิงกำหนด (Deterministic Encryption)

เพราะระบบเป็นฟังก์ชันกำหนดแน่นอนของ $(\text{กุญแจ}, \text{ภาพ})$ ผู้โจมตีจึงดำเนินการโจมตีต่อไปนี้ได้

- **การโจมตีจากพจนานุกรม (Dictionary Attack)** หากภาพต้นฉบับมาจากคลังที่คาดเดาได้ (เช่น ภาพหน้าปก โลโก้ หรือรูปผู้ต้องสงสัยชุดเล็ก) ผู้โจมตีสร้างตารางรหัสล่วงหน้าเทียบได้
- **การโจมตีเพื่อจับคู่ความเท่ากัน (Equality Detection)** ข้อความเข้ารหัสที่เหมือนกันย่อมหมายถึงภาพต้นฉบับที่เหมือนกัน
- **การโจมตีแบบเลือกข้อความต้นฉบับอย่างปรับตัว (Adaptive CPA)** การเข้ารหัสซ้ำด้วยกุญแจเดิมให้ข้อมูลเปรียบเทียบเชิงเพิ่มพูน

### 5.8 ความอ่อนไหวต่อการดัดแปลงข้อมูลและการขาดรหัสยืนยันตัวตน (Malleability, No MAC)

เปเปอร์ไม่มีกลไกตรวจสอบความถูกต้องสมบูรณ์ของข้อมูล (Message Authentication Code, MAC) และไม่มีลายเซ็นดิจิทัล

- **การโจมตีพลิกบิตโดยไม่ต้องมีกุญแจ (Unauthenticated Bit-Flip)** ผู้โจมตีที่ดักช่องทางได้สามารถแก้บิตในไฟล์เสียงเพื่อเปลี่ยนค่าพิกเซลปลายทางได้แบบเลือกเจาะจง โดยไม่ต้องรู้กุญแจ หากบิตที่แก้ยังคงให้คำที่ถูกต้องในชุด DCC ค่าพิกเซลปลายทางจะเปลี่ยนตามที่ผู้โจมตีกำหนด
- **การโจมตีตัดทอน (Truncation Attack)** การตัดไฟล์เสียงบางส่วนจะทำให้จำนวนรหัสที่กู้ได้น้อยกว่าจำนวนพิกเซลเป้าหมาย โดยไม่มีกลไกตรวจจับ
- สังเกตว่าการสลับตำแหน่งแบบตายตัว $\pi$ ไม่มีการขึ้นต่อค่าและตำแหน่งของพิกเซลก่อนหน้า จึงไม่มีการเชื่อมโยงแบบลูกโซ่ (Chaining) ที่จะชดเชยการแก้ไขได้เลย

### 5.9 การยุบตัวของเมล็ดกุญแจจริง (Seed Space Collapse)

เปเปอร์ไม่ระบุว่าเมล็ดกุญแจถูกแปลงเป็นการเรียงสับเปลี่ยนอย่างไร และไม่ระบุขนาดหรือการแจกแจงของเมล็ดกุญแจ ตัวอย่างเดียวที่ให้คือคำว่า Shannon

- หากเมล็ดกุญแจเป็น **คำที่ผู้ใช้พิมพ์** ปริภูมิเมล็ดกุญแจจริงคือขนาดของพจนานุกรม (Dictionary) หรือวลีที่คาดเดาได้ ซึ่งเล็กมาก คำว่า Shannon มีเอนโทรปีโดยประมาณ 10 ถึง 20 บิต
- หากเมล็ดกุญแจป้อนเข้าตัวสร้างเลขสุ่มเทียมแบบมาตรฐาน (เช่น randperm ใน MATLAB) ปริภูมิที่เข้าถึงได้จริงถูกจำกัดด้วยขนาดหน่วยความจำของเมล็ด ซึ่งโดยทั่วไปต่ำกว่า $2^{64}$ มาก
- **ไม่มีการพิสูจน์ว่าเมล็ดกุญแจทุกค่าจับคู่กับการเรียงสับเปลี่ยนได้ครบทั้ง $256!$ แบบ** การที่ $256!$ เป็นจำนวนการเรียงสับเปลี่ยนทั้งหมดไม่ได้หมายความว่าทุกแบบเข้าถึงได้จากเมล็ดที่ใช้จริง
- ปริภูมิที่แท้จริงคือ **จำนวนเมล็ดกุญแจที่ผู้ใช้เลือกได้จริง** ซึ่งมักน้อยกว่าที่อ้างไว้หลายร้อยอันดับขนาด

### 5.10 การแจกจ่ายกุญแจและช่องทางที่เปเปอร์เสนอ (Key Distribution Weakness)

เปเปอร์เสนอให้ส่งไฟล์เสียงที่เข้ารหัสผ่าน WhatsApp และส่งกุญแจผ่านอีเมล

- นี่คือการแยกช่องทาง (Out-of-Band Channel) ซึ่งป้องกันได้เฉพาะผู้ดักฟังช่องทางเดียว แต่อีเมลและ WhatsApp ทั้งคู่เป็นช่องทางที่ผู้ให้บริการอ่านได้ (Provider-Readable) และไม่ให้การรับประกันความลับระดับวิศวกรรม
- ปัญหาที่ร้ายแรงกว่าคือ **ความเสียหายจากตัวแปลงรหัสเสียง (Audio Codec Corruption)** WhatsApp บีบอัดเสียงด้วยตัวแปลงรหัสแบบสูญเสีย (Lossy Codec เช่น Opus) ซึ่งเปลี่ยนค่าตัวอย่างไม่มากนัก แต่เพราะข้อมูลถูกเข้ารหัสระดับ 16 บิตต่อหนึ่งคำ การเปลี่ยนตัวอย่างเพียงเล็กน้อยย่อมทำลายบิตและทำให้ตำแหน่งหัวรหัส `11` เพี้ยนไปทั้งหมด การถอดรหัสจะล้มเหลวอย่างสิ้นเชิง
- เปเปอร์ **ไม่ทดสอบความทนทานต่อการบีบอัดเสียงเลย** การเสนอช่องทางที่ทำลายข้อมูลของตนเองจึงเป็นการขัดแย้งเชิงออกแบบ (Design Contradiction) ที่ชัดเจน

### 5.11 (Al-Hyari และคณะ 2024) การเรียงสับเปลี่ยนที่ไม่ขึ้นกับข้อความต้นฉบับ

ระบบของ Al-Hyari และคณะ 2024 ใช้การสลับแถวและสลับคอลัมน์ที่สร้างจากแผนที่ความโกลาหล (Chaotic Map) ซึ่ง **ขึ้นกับกุญแจเพียงอย่างเดียว ไม่ขึ้นกับข้อความต้นฉบับ** ร่วมกับการแพร่กระจายด้วยการดำเนินการ XOR กับกุญแจ 2 มิติ

นี่คือโครงสร้างที่ Solak, Çokal, Yıldız และ Biyikoğlu (2010) ทำลายสำหรับระบบ Fridrich และเป็นโครงสร้างเดียวกับที่ Çokal และ Solak (2009) ทำลายมาก่อน

การโจมตีที่ใช้ได้ทันที

- **การกู้กระแสกุญแจ (Keystream Recovery)** เพราะการแพร่กระจายเป็น $C = P \oplus K_{\text{map}}$ หากมีคู่ภาพต้นฉบับและภาพเข้ารหัสที่รู้หนึ่งคู่ จะได้ $K_{\text{map}} = C \oplus P$ ซึ่งใช้ถอดรหัสภาพอื่นทุกภาพที่ใช้กุญแจเดียวกันได้
- **การกู้การเรียงสับเปลี่ยน (Permutation Recovery)** ตามผลของ Li และ Lo (2011) รหัสที่มีการสลับตำแหน่งแบบพึ่งกุญแจเพียงอย่างเดียวถูกทำลายด้วยจำนวนภาพที่รู้จำนวน $O(\lceil \log_L(MN) \rceil)$ ภาพ ซึ่งสำหรับภาพขนาด $512 \times 768$ คือหลักสิบภาพ
- เปเปอร์เองยอมรับในงานอนาคตว่ายังต้อง "ทำการวิเคราะห์รหัสลับเพิ่มเติมเพื่อพิสูจน์ความแข็งแกร่ง เช่น การโจมตีแบบมีแต่ข้อความเข้ารหัส แบบรู้ข้อความต้นฉบับ และแบบคนกลาง" ซึ่งเท่ากับยอมรับว่ายังไม่ได้ทดสอบ

### 5.12 (Al-Hyari และคณะ 2024) การเสื่อมสภาพเชิงพลวัตของแผนที่โลจิสติกและชุดทดสอบ NIST

- **การเสื่อมสภาพเชิงพลวัต (Dynamical Degradation)** Li, Chen และ Mou (2005) แสดงว่าแผนที่ความโกลาหลแบบเชิงเส้นเป็นช่วง ๆ เมื่อทำงานบนจำนวนจำกัดหลัก (Finite Precision) จะมีวงโคจรสั้นลงและเอนโทรปีลดลงอย่างรุนแรง งานของ Yang และคณะ (2016) ยังแสดงว่าสามารถสร้างโครงข่ายส่งสภาวะ (State-Mapping Network) เพื่อทำนายอนาคตของแผนที่ได้จากสภาวะบางส่วน
- **ชุดทดสอบ NIST** เปเปอร์ระบุว่า "หากแปดจากสิบสายทดสอบผ่าน ถือว่าผ่าน" ซึ่งเป็นเกณฑ์ที่ผ่อนปรนเกินจริง รายงานของเปเปอร์เองมีหลายชุดทดสอบที่ผ่านเพียง 8 จาก 10 และ 9 จาก 10 การรายงานว่า "ผ่านการทดสอบส่วนใหญ่" (Passed Most Tests) เป็นการนำเสนอที่เลือกข้าง (Selective Reporting)
- **การทดสอบความไวต่อกุญแจที่ไม่มีนัยสำคัญ** เปเปอร์รายงานค่า MSE และ PSNR ระหว่างการเปลี่ยนกุญแจหนึ่งหลัก ซึ่งเป็นข้อเท็จจริงของทุกระบบ ไม่ได้แยกแยะระบบที่ปลอดภัยออกจากระบบที่ไม่ปลอดภัยเลย

## 6. คอขวดเชิงปฏิบัติ (Practical Bottlenecks)

### 6.1 การขยายขนาดข้อมูลประมาณ 6 เท่า

ผู้วิจารณ์คำนวณความยาวรหัสคอลลัทซ์เฉลี่ยสำหรับค่าพิกเซลทั้ง 256 ค่า ได้ 47.98 บิตต่อพิกเซล เมื่อเทียบกับภาพต้นฉบับ 8 บิตต่อพิกเซล

| ขนาดภาพ | ภาพต้นฉบับ | สายบิตที่เข้ารหัส | ไฟล์เสียงที่ต้องส่ง | อัตราขยาย |
|:---|:---:|:---:|:---:|:---:|
| $512 \times 512$ | 262,144 ไบต์ | 12,577,792 บิต | 1,572,224 ไบต์ | 6.00 เท่า |
| $256 \times 256$ | 65,536 ไบต์ | 3,144,448 บิต | 393,056 ไบต์ | 6.00 เท่า |

- อัตราขยายคงที่ประมาณ 6 เท่า ไม่ว่าจะใช้ภาพขนาดใด เพราะค่าเฉลี่ยของความยาวรหัสแทบไม่ขึ้นกับขนาดภาพ
- ระบบ **ไม่มีการบีบอัด** แม้ตัวรหัสเองจะกวาดข้อมูลที่ซ้ำซ้อนสูง (Redundancy) ของภาพธรรมชาติออกไปแล้วก็ตาม
- เมื่อรวมกับหัวแฟ้ม WAV และการเติมศูนย์ในคำสุดท้าย ขนาดจริงจะยิ่งโตขึ้นอีกเล็กน้อย
- คำกล่าวในเปเปอร์ว่า "ไม่มีความสัมพันธ์ระหว่างขนาดภาพกับความยาวของเสียง" **ไม่ถูกต้อง** เพราะความยาวเสียงเป็นฟังก์ชันกำหนดแน่นอนของขนาดภาพและผลรวมของความยาวรหัส ซึ่งขึ้นกับฮิสโตแกรมของค่าในภาพ

### 6.2 รูปแบบผลลัพธ์เป็นเสียงและความเสียหายจากตัวแปลงรหัส

- ผลลัพธ์เป็นไฟล์เสียงไม่ใช่ไฟล์ภาพ ทำให้ pipeline ปลายทางต้องแปลงไฟล์และเพิ่มความเสี่ยง
- หากต้องส่งผ่านช่องทางบีบอัดเสียง ข้อมูลจะเสียหายแบบถอดรหัสไม่ได้ (รายละเอียดในหัวข้อ 5.10)
- หากต้องการเก็บเป็นไฟล์เสียงแบบไม่สูญเสีย (Lossless WAV) จะได้ไฟล์ขนาดใหญ่กว่าภาพเดิมหกเท่า ซึ่งในทางปฏิบัติแย่กว่าการใช้ AES ร่วมกับโหมดที่เหมาะสม ซึ่งมีการขยายขนาดเป็นศูนย์
- การแปลงค่าตัวอย่างกลับเป็นหนึ่งใน 65536 ระดับไม่มีการระบุความละเอียดและรูปแบบการเก็บอย่างชัดเจน ทำให้เสี่ยงต่อความคลาดเคลื่อนเชิงตัวเลข (Numerical Precision Loss)

### 6.3 อัตราการส่งผ่าน (Throughput)

สำหรับ Al-Hyari และคณะ 2024

- เวลาเข้ารหัสเฉลี่ยของภาพขนาด $512 \times 768 \times 3$ คือ 2.4444 วินาที
- อัตราการส่งผ่านที่รายงานคือ 0.4606 เมกะบิตต่อวินาที (471.6 กิโลบิตต่อวินาที)
- เปเปอร์เปรียบเทียบว่าดีกว่าวิธีหนึ่ง 1.56 เท่า แต่ **ต่ำกว่าวิธีแบบไฮเปอร์เคออติก (Hyperchaotic) ที่ 636 กิโลบิตต่อวินาที**
- เมื่อเทียบกับ AES-GCM หรือ ChaCha20-Poly1305 ซึ่งใช้ชุดคำสั่งฮาร์ดแวร์เร่งความเร็ว (AES-NI) ทำได้ระดับหลายกิกะบิตต่อวินาทีต่อหนึ่งคอร์ ระบบนี้ช้ากว่าอย่างน้อย **สี่อันดับขนาด** หรือประมาณหลายพันถึงหลายหมื่นเท่า ผู้วิจารณ์ย้ำว่าเป็นการเปรียบเทียบเชิงขนาด (Order of Magnitude) ไม่ใช่การวัดบนเครื่องเดียวกัน

สำหรับ Ballesteros และคณะ 2018 ไม่มีการรายงานเวลาเลย ซึ่งเป็นช่องว่างที่สำคัญ เพราะความซับซ้อนของเวลาหลักคือการค้นหาคำในโครงสร้าง DCC ซึ่งเป็น $O(\log 256)$ ในกรณีใช้การค้นแบบไบนารี แต่จะกลายเป็น $O(256)$ ในกรณีค้นแบบเชิงเส้นต่อหนึ่งพิกเซล ซึ่งจะทำให้ระบบช้าอย่างรุนแรง

### 6.4 การไม่ระบุขั้นตอนให้ชัดเจนและการทำซ้ำไม่ได้ (Under-specification and Reproducibility)

เปเปอร์ 2018 ปล่อยรายละเอียดสำคัญที่จำเป็นต่อการทำซ้ำไว้ไม่ชัดเจน

1. **การแปลงเมล็ดกุญแจเป็นการเรียงสับเปลี่ยน** ไม่มีการระบุขั้นตอนวิธี
2. **การวางตำแหน่งในสายบิต** ไม่ระบุว่าพิกเซลคู่หรือคี่ไปไว้หน้าและหลังอย่างไรเมื่อรหัสมีความยาวต่างกัน
3. **การนับรอบของรหัสคอลลัทซ์** ไม่สอดคล้องกันเองระหว่างหัวข้อ 2.1 และหัวข้อ 3 (ดูหัวข้อ 4.3)
4. **ช่วงการค้นหาในโครงสร้าง DCC** ไม่ระบุว่าใช้การค้นแบบใด
5. **ลิงก์ข้อมูลใน Mendeley** อยู่ในรูปแบบ Draft URL ที่มีโทเคน ซึ่งเสี่ยงต่อการหมดอายุ การทำซ้ำจากข้อมูลผู้เขียนจึงไม่ได้รับประกัน

สำหรับนิสิตปริญญาตรี นี่หมายความว่า **นิสิตจะไม่สามารถทำซ้ำผลลัพธ์ของเปเปอร์ได้ตรงตามตัวเลข** และจะต้องตีความและตัดสินใจออกแบบเอง ซึ่งเสี่ยงต่อการเกิดความเข้าใจผิดว่าตนทำผิด

### 6.5 การทดสอบบนชุดข้อมูลเล็กและไม่มีความหลากหลาย

- Ballesteros และคณะใช้ภาพ 20 ภาพ และกุญแจ 5 ตัวต่อภาพ รวม 100 ตัวอย่าง แต่ **ไม่ระบุขนาดภาพ ขนาดความละเอียด หรือแหล่งที่มาของภาพ**
- Al-Hyari และคณะใช้ชุด Kodak Lossless True Color Image Suite เพียง 24 ภาพ ซึ่งเป็นชุดทดสอบมาตรฐานที่รู้จักกันดีในชุมชน ทำให้ผู้โจมตีสามารถเตรียมตารางล่วงหน้าได้ และไม่มีการทดสอบกับภาพที่มีฮิสโตแกรมสุดโต่งแบบอื่นนอกจากภาพดำและขาวสนิท
- **ไม่มีการทดสอบหลายกุญแจบนภาพเดียวกันในแง่การโจมตี** (Multi-Key Cryptanalysis) ซึ่งเป็นการทดสอบที่จำเป็นสำหรับระบบที่ไม่มีนอนซ์

### 6.6 การขาดการพิสูจน์ความปลอดภัยเชิงรูปแบบ

ทั้งสองเปเปอร์ **ไม่มีการพิสูจน์ความปลอดภัยเชิงรูปแบบเลย**

- ไม่มีนิยามของแบบจำลองผู้โจมตี
- ไม่มีการลดทอนปัญหาไปสู่ปัญหาที่ยาก (เช่น Subset Sum หรือ Learning with Errors)
- ไม่มีการพิสูจน์ IND-CPA หรือ IND-CCA
- ไม่มีการวิเคราะห์เชิงเส้นกำกับของความได้เปรียบ (Advantage) ของผู้แยกแยะ

ในสาขาวิทยาการรหัสลับ ระบบที่ไม่มีการพิสูจน์ความปลอดภัยเชิงรูปแบบจะถูกจัดเป็นระบบที่ยังไม่ได้รับความเชื่อถือ (Unproven) ซึ่งเป็นสถานะเริ่มต้นเสมอ จนกว่าจะมีการวิเคราะห์เชิงปฏิปักษ์ที่ครบถ้วน

### 6.7 คอขวดระดับสถาปัตยกรรมฮาร์ดแวร์ (Hardware-Level Bottlenecks)

นอกจากความซับซ้อนเชิงเส้นกำกับแล้ว ระบบตระกูลนี้ยังมีปัญหาที่ระดับไมโครสถาปัตยกรรมของซีพียู ซึ่งเป็นเหตุผลที่ความเร็วที่วัดได้ต่ำกว่าที่คาดการณ์จากความซับซ้อนเพียงอย่างเดียว

- **การทำนายทิศทางการแตกกิ่งผิดพลาด (Branch Misprediction)** การคำนวณวงโคจรคอลลัทซ์ต้องทดสอบ `if n % 2 == 0` ซ้ำหลายสิบรอบต่อหนึ่งพิกเซล ทำให้ตัวทำนายทิศทางของซีพียูล้มเหลวบ่อยครั้ง และสูญเสียรอบสัญญาณ (Clock Cycles) ไปกับการล้างท่อคำสั่ง (Pipeline Flush)
- **การขัดขวางการประมวลผลแบบเวกเตอร์ (SIMD)** การดำเนินการแบบมีเงื่อนไขที่ขึ้นกับค่าของแต่ละข้อมูล (Data-Dependent Branch) ทำให้ไม่สามารถใช้ชุดคำสั่ง SIMD หรือ AVX ได้อย่างเต็มที่ จึงสูญเสียความได้เปรียบจากการประมวลผลแบบขนานระดับบิต ซึ่งเป็นความได้เปรียบหลักของรหัสลับสมัยใหม่
- **การเข้าถึงหน่วยความจำแบบกระโดด (Irregular Memory Access)** การสลับตำแหน่งพิกเซลตามดัชนีที่มาจากลำดับความโกลาหลทำให้รูปแบบการเข้าถึงหน่วยความจำไม่ต่อเนื่อง ส่งผลให้แคช (Cache) มีอัตราการพลาดสูง
- **การรั่วไหลผ่านเวลาการทำงาน (Timing Side Channel)** จำนวนรอบของวงโคจรคอลลัทซ์ขึ้นอยู่กับค่าพิกเซลต้นฉบับโดยตรง ดังนั้นเวลาที่ใช้เข้ารหัสจึงขึ้นอยู่กับเนื้อหาของภาพ ซึ่งเป็นช่องทางข้างเคียง (Side Channel) เชิงเวลาแบบคลาสสิกที่เปิดเผยข้อมูลบางส่วนได้โดยไม่ต้องใช้กุญแจ

ข้อสุดท้ายนี้เป็นประเด็นที่ลึกกว่าระดับปริญญาตรี แต่นิสิตที่มีพื้นฐานระบบคอมพิวเตอร์แข็งสามารถต่อยอดได้

## 7. ความเสี่ยงในการให้คำปรึกษานิสิตปริญญาตรี (Advising Risks)

### 7.1 การจัดอันดับ Tier S ในเอกสารภายในขัดกับข้อเท็จจริง

เอกสาร `guides/PAPER_BENCHMARK_RANKING.md` จัดอันดับหัวข้อ Collatz Image Encryption เป็น **Tier S อันดับ 1** โดยให้คะแนนความเสี่ยงในการคุมว่า **"ต่ำมาก (Safe Zone)"** ให้คะแนนความประจักษ์ของผลลัพธ์ห้าดาว และให้หัวข้อนี้เป็น **"Flagship Option"**

**ความเสี่ยงคือการจัดอันดับนี้สร้างขึ้นจากตัวชี้วัดที่เปเปอร์รายงานเอง ซึ่งเป็นตัวชี้วัดที่ไม่ผ่านการวิเคราะห์เชิงปฏิปักษ์** การให้คะแนน "ความเสี่ยงต่ำ" จากระบบที่มีช่องโหว่ระดับทำลายทั้งหมดในข้อความที่รู้หนึ่งภาพ คือการส่งต่อข้อผิดพลาดให้แก่นิสิตโดยตรง

นี่คือตัวอย่างของความล้มเหลวเชิงระเบียบวิธี (Methodological Failure) ในตัวเอกสารให้คำปรึกษาเอง ซึ่งเป็นความล้มเหลวแบบเดียวกับที่เอกสารวิจารณ์ในเปเปอร์

### 7.2 ความเสี่ยงที่นิสิตจะเรียนรู้ระเบียบวิธีที่ผิด

ความเสี่ยงที่แท้จริงไม่ใช่ "นิสิตทำโครงงานไม่สำเร็จ" แต่คือ "นิสิตทำโครงงานสำเร็จและจำบทเรียนผิด"

บทเรียนที่นิสิตจะรับไปโดยไม่รู้ตัวจากเปเปอร์นี้

1. **"ผ่านตัวชี้วัด NPCR, UACI, เอนโทรปี = ปลอดภัย"** ซึ่งเป็นเท็จ ตัวชี้วัดเหล่านี้บ่งชี้คุณภาพการกระจายตัวของผลลัพธ์ ไม่ใช่ความต้านทานต่อผู้โจมตีที่เลือกอินพุตได้
2. **"ขนาดปริภูมิกุญแจใหญ่มากหมายถึงปลอดภัย"** ซึ่งเป็นเท็จ ตัวชี้วัดที่เข้าถึงได้จริงคือกุญแจสมมูล ซึ่งมักเล็กกว่าปริภูมิที่อ้างไว้หลายร้อยอันดับขนาด
3. **"ระบบที่พึ่งพากุญแจเท่านั้นยิ่งปลอดภัย"** ซึ่งผกผันกับความจริง ระบบที่ไม่มีนอนซ์คือระบบที่เสี่ยงที่สุด
4. **"ความยากของข้อความคาดการณ์ทางคณิตศาสตร์ให้ความแข็งแกร่งเชิงรหัสลับ"** ซึ่งเป็นเท็จ สมมติฐานคอลลัทซ์ไม่มีความเกี่ยวข้องกับ CSPRNG
5. **"ตีพิมพ์ในวารสารที่ตรวจทานโดยผู้ทรงคุณวุฒิแล้วเท่ากับถูกต้อง"** ซึ่งเป็นเท็จ เปเปอร์ทั้งสองฉบับผ่านการตรวจทานและยังคงมีข้อผิดพลาดทางคณิตศาสตร์พื้นฐาน

นิสิตที่จบสัมมนาโดยถือบทเรียนทั้งห้าข้อนี้ไป แล้วไปทำงานด้านความปลอดภัยสารสนเทศจริง จะเป็นความเสี่ยงที่ร้ายแรงกว่าการส่งรายงานช้า

### 7.3 ภาพลวงตาจากตัวชี้วัดและอคติยืนยัน (Metric Illusion and Confirmation Bias)

ระบบนี้ให้ภาพลวงตาของความสำเร็จอย่างรุนแรง

- **ผลลัพธ์ที่ประจักษ์ด้วยตาเปล่า (Visual Impact)** ภาพถ่ายธรรมชาติกลายเป็นสัญญาณรบกวน และถอดกลับได้สมบูรณ์แบบ 100 เปอร์เซ็นต์ นี่คือความพึงพอใจทางประสาทสัมผัสที่สร้างความมั่นใจโดยไม่มีเหตุผลรองรับ
- **ตัวเลขที่ดูเป็นวิทยาศาสตร์ (Scientific-Looking Numbers)** ค่าเอนโทรปี 7.99 ค่า NPCR 99.6 เปอร์เซ็นต์ ค่า UACI 33.46 เปอร์เซ็นต์ ล้วนเป็นตัวเลขที่ทำให้ผู้ประเมินรู้สึกว่า "มีหลักฐานเชิงประจักษ์" ทั้งที่ตัวเลขเหล่านี้เป็นเพียงคุณสมบัติของผลลัพธ์ (Output Distribution) ไม่ใช่ของคุณสมบัติของความต้านทานต่อการโจมตี
- **อคติยืนยัน (Confirmation Bias)** กระบวนการทำโครงงานแบบ "เขียนโค้ด, รันทดสอบ, รายงานตัวเลข, สรุปว่าปลอดภัย" เป็นกระบวนการที่ออกแบบมาเพื่อยืนยันสมมติฐานของตัวเอง ผู้เรียนจะไม่มีวันพบว่าตัวเองผิด
- **การเปรียบเทียบผิดบริบท (Category Error)** การที่เอกสารภายในเรียกการแปลงภาพเป็นไฟล์เสียงว่าเป็นเรื่องของ "การซ่อนข้อมูล (Steganography)" หรือการแปลงรหัส (Transcoding) นั้นไม่ถูกต้องทั้งหมด เพราะสเตกาโนกราฟีไม่ใช่เป้าหมายของเปเปอร์ แต่ประเด็นที่ถูกต้องคือ เปเปอร์ไม่ได้แสดงสมบัติทางความปลอดภัยแบบฟังก์ชันทางเดียว (One-Way Property) แต่อย่างใด การติดป้ายผิดประเภทเช่นนี้จะทำให้นิสิตโต้แย้งไม่ตรงประเด็น

**การทดลองที่เปิดโปงภาพลวงตานี้** ผู้วิจารณ์เสนอให้สร้างระบบเข้ารหัสที่รู้อยู่แล้วว่าพัง (เช่น การเรียงสับเปลี่ยนเอกลักษณ์รวมกับการ XOR ด้วยมาราสก์คงที่) แล้วแสดงว่ามันได้ค่าเอนโทรปีประมาณ 8.0 และ NPCR ประมาณ 99.6 เปอร์เซ็นต์ครบถ้วน ซึ่งเป็นหลักฐานชัดเจนว่าตัวชี้วัดเหล่านี้ไม่แยกแยะระบบที่ปลอดภัยออกจากระบบที่พังแล้ว

### 7.4 ความน่าเชื่อถือจากวารสารและภาพลวงตาของการตรวจทาน (Peer-Review Illusion)

- *Entropy* เป็นวารสารของ MDPI ซึ่งมีค่าใช้จ่ายในการตีพิมพ์แบบเปิด (Article Processing Charge, APC) และมีข้อวิจารณ์ในวงกว้างเรื่องความเข้มงวดของกระบวนการตรวจทาน
- *IEEE Access* เป็นวารสารที่ผ่านการตรวจทาน แต่ใช้กระบวนการตรวจทานแบบรวดเร็ว และมีอัตราการรับตีพิมพ์สูง
- **ประเด็นไม่ใช่เรื่องคุณภาพของวารสาร** แต่คือความคาดหมายของนิสิตว่างานที่ตีพิมพ์ผ่านการตรวจทานแล้วจะไม่มีข้อผิดพลาดทางคณิตศาสตร์พื้นฐาน ซึ่งตรงกับกรณีนี้
- เมื่อใช้เปเปอร์นี้เป็น "ต้นแบบเชิงระเบียบวิธี" นิสิตจะฝึกใช้ข้อความที่ตีพิมพ์เป็นบรรทัดฐานโดยไม่ตั้งคำถาม ซึ่งขัดกับหัวใจของวิธีการทางคณิตศาสตร์

### 7.5 รหัสตั้งต้นในคู่มือ guide-04 และข้อบกพร่องของรหัส

คู่มือ `guides/guide-04-collatz-image-encryption.md` มีโค้ดตั้งต้นภาษา Python ที่ควรได้รับการแก้ไขก่อนส่งถึงนิสิต ผู้ตรวจพบข้อบกพร่องดังนี้

1. **โค้ดไม่ตรงกับเปเปอร์ต้นฉบับ** โค้ดที่ให้เป็นระบบเรียงสับเปลี่ยนพิกัดด้วยการเรียงตามดัชนี (Argsort) ร่วมกับการ XOR กรองข้อมูลแบบลูกโซ่ (Chained XOR) ซึ่งเป็นระบบแบบสับเปลี่ยนและแพร่กระจายทั่วไป **คนละระบบกับ Ballesteros 2018** ที่ใช้รหัสความยาวแปรผันและให้ผลลัพธ์เป็นเสียง
2. **ตัวชี้วัดที่คู่มือเรียกว่า "มาตรฐานสากล" (NPCR, UACI, เอนโทรปีบนภาพ) ไม่ปรากฏในเปเปอร์ต้นฉบับเลย** ทำให้เกิดการอ้างอิงที่ไม่ตรงกัน (Misattribution) ระหว่างคู่มือกับเปเปอร์
3. **การเรียกใช้ `np.argsort` ด้วยอัลกอริทึมเริ่มต้น (Quicksort) ไม่เสถียร (Not Stable)** เมื่อค่ามีการซ้ำ และจำนวนซ้ำมีมากมายเพราะวงโคจรคอลลัทซ์วนกลับมาสู่ค่าเดิมบ่อย ลำดับผลลัพธ์จึงต่างกันข้ามแพลตฟอร์ม และทำให้การทำซ้ำปิดทองไม่ได้
4. **ตัวสร้างสายคอลลัทซ์ใช้การล้นแบบ 64 บิต (Wraparound)** ซึ่งจะเข้าวงรอบที่ไม่ใช่วง 4-2-1 แต่ความยาวรอบจริงไม่เคยถูกวิเคราะห์ ผลที่ตามมาคือสายที่ได้ไม่ใช่สายที่กระจายตัวดี
5. **ไม่มีนอนซ์หรือ IV ในโค้ด** เช่นเดียวกับเปเปอร์ต้นฉบับ และกระแส `collatz_stream % 256` ถูกใช้ซ้ำข้ามภาพทั้งชุด
6. **ตัวสับเปลี่ยน (Permutation Indices) ถูกส่งคืนเป็นส่วนหนึ่งของกุญแจถอดรหัส** ขนาดข้อมูลของมันคือ $L \log_2 L$ บิต ซึ่งสำหรับภาพ $512 \times 512$ คือหลายเมกะบิต เทียบเท่ากับการส่งกุญแจที่มีขนาดใหญ่กว่าข้อความ

### 7.6 ความเสี่ยงเชิงจริยธรรมและมาตรฐานการประเมิน

- **ความเสี่ยงทางวิชาการ** หากรายงานสัมมนาของนิสิตคัดลอกข้ออ้างเรื่อง "ความลับสมบูรณ์" โดยไม่ตรวจสอบ รายงานนั้นจะมีการกล่าวอ้างทางคณิตศาสตร์ที่เป็นเท็จ และอาจารย์ที่ปรึกษาซึ่งลงนามรับรองจะร่วมรับผิดชอบทางวิชาการ
- **ความเสี่ยงทางจริยธรรม** หากนิสิตนำระบบนี้ไปใช้จริงเพื่อคุ้มครองข้อมูลส่วนบุคคลของผู้อื่น จะสร้างความเชื่อมั่นที่ผิด (False Confidence) ซึ่งอันตรายกว่าการไม่มีระบบเข้ารหัสเสียอีก เพราะผู้ใช้จะประพฤติตัวประมาท
- **ความเสี่ยงต่อระเบียบวิธีของหลักสูตร** การประเมินงานแบบเดิมที่ให้คะแนนจาก "จำนวนตัวชี้วัดที่ผ่าน" จะให้คะแนนเต็มกับระบบที่พังแล้ว ซึ่งเป็นการบ่มเพาะพฤติกรรมที่ผิดในหลักสูตรคณิตศาสตร์ประยุกต์

### 7.7 ความเสี่ยงต่อโครงการต่อยอดเล่มจบห้าบท

เอกสารภายในหลายฉบับอ้างว่านักศึกษาสามารถต่อยอดหัวข้อนี้เป็น **เล่มโครงงานวิจัยปริญญาตรี 01417499 ห้าบทได้ทันที** ซึ่งเป็นความจริงในเชิงรูปแบบ แต่เป็นความเสี่ยงในเชิงเนื้อหา

- หากเล่มจบทั้งห้าบทสร้างบนระบบที่ไม่ปลอดภัย เล่มจบทั้งหมดจะเป็นงานที่ "พิสูจน์ความปลอดภัยของสิ่งที่พิสูจน์ได้ว่าพังแล้ว"
- หากนิสิตต้องการทำเล่มจบให้มีคุณค่า ต้องเปลี่ยนมุมจาก "สร้าง" เป็น "ทำลายและซ่อม" ซึ่งจะเพิ่มงานประมาณสองเท่า แต่ให้คุณค่าทางวิชาการสูงกว่ามาก และมีโอกาสตีพิมพ์ในที่ประชุมระดับนักศึกษา
- ความเสี่ยงด้านเวลา การทำซ้ำเปเปอร์ที่ระบุขั้นตอนไม่ชัดเจน (หัวข้อ 6.4) จะกินเวลาไปกับการตีความมากกว่าการทดลองจริง

### 7.8 ความเสี่ยงด้านการอ้างอิง

- เอกสารภายในเรียกเปเปอร์ 2024 ว่า "Obimbo 2024" แต่ **ผู้แต่งลำดับแรกคือ A. Al-Hyari** ส่วน C. Obimbo เป็นผู้แต่งลำดับที่สอง การอ้างอิงแบบย่อนี้ทำให้เกิดความเข้าใจผิดเรื่องผู้ประพันธ์ และหากนิสิตเขียนบรรณานุกรมตามจะได้รายการอ้างอิงที่ผิดรูปแบบ
- ต้องอ้างอิงเป็น Al-Hyari, A., Obimbo, C., Abu-Faraj, M. M. & Al-Taharwa, I. (2024) เป็นต้นไป

## 8. การเปลี่ยนข้อบกพร่องให้เป็นโอกาสวิจัยของนิสิต (Turning Flaws into Research Opportunities)

หัวใจของการให้คำปรึกษาคือ **ไม่โยนเปเปอร์ทิ้ง** แต่เปลี่ยนมันจาก "ต้นแบบ" เป็น **"ชิ้นงานทดลอง" (Specimen)** นิสิตได้ทั้งความตื่นเต้นจากผลลัพธ์ที่เป็นรูปภาพ และได้เรียนรู้วิทยาการรหัสลับอย่างจริงจังไปพร้อมกัน

### 8.1 เส้นทางวิจัยที่แนะนำ (Research Tracks)

**เส้นทางที่ 1: ห้องปฏิบัติการทำลาย (Break-It Lab)**

- **โจทย์วิจัย** ระบบของ Ballesteros 2018 ต้านทานการโจมตีแบบเลือกข้อความต้นฉบับได้จริงหรือไม่
- **วิธีทำ** เขียนภาพทดสอบขนาด $256 \times 256$ ที่มีค่าระดับสีครบทั้ง 256 ค่า วางตามตำแหน่งที่รู้ ส่งเข้าสู่ระบบ ถอดตาราง $\sigma_k$ และถอดรหัสภาพทดสอบทั้ง 20 ภาพ
- **ชิ้นงาน** สคริปต์โจมตี, ตารางกุญแจสมมูล 256 รายการ, ภาพที่ถอดได้ทั้งหมด, ตารางเวลาที่ใช้
- **ระดับความยาก** ระดับกลาง (นิสิตปีสามทำได้ภายในสองสัปดาห์)
- **ผลลัพธ์ที่คาดหมาย** พบว่าการถอดรหัสสำเร็จภายในเวลาไม่ถึงวินาที ซึ่งเป็นการพิสูจน์เชิงประจักษ์ที่ไม่มีวันลืม

**เส้นทางที่ 2: การโจมตีแบบรู้ข้อความต้นฉบับด้วยภาพธรรมชาติ (One Known Image)**

- **โจทย์วิจัย** ภาพถ่ายธรรมชาติเพียงหนึ่งภาพเพียงพอต่อการกู้กุญแจสมมูลหรือไม่ และมีค่าระดับสีครบทั้ง 256 ค่าจริงหรือไม่
- **วิธีทำ** รันการทดลองกับภาพจากหลายชุดข้อมูล (Kodak, USC-SIPI, BOSSBase) และวัดสัดส่วนภาพที่มีค่าระดับสีครบ 256 ค่า
- **ชิ้นงาน** สถิติความครอบคลุมของค่าระดับสีในภาพธรรมชาติ กับการโจมตีที่สำเร็จหรือล้มเหลวพร้อมเหตุผล
- **ระดับความยาก** ระดับกลาง
- **ผลลัพธ์ที่คาดหมาย** พบว่าภาพธรรมชาติเกือบทั้งหมดมีค่าระดับสีครบ และสัดส่วนที่ทำได้สำเร็จสูงมาก

**เส้นทางที่ 3: การโจมตีแบบมีแต่ข้อความเข้ารหัสด้วยการวิเคราะห์ความถี่**

- **โจทย์วิจัย** ค่าเอนโทรปีที่ลดลงสามารถแปลงเป็นความได้เปรียบของผู้โจมตีได้เชิงปริมาณเท่าใด
- **วิธีทำ** แก้ปัญหาการจับคู่ฮิสโตแกรม (Assignment Problem) ด้วยขั้นตอนวิธีฮังการี (Hungarian Algorithm) และวัดความแม่นยำในการกู้ $\sigma_k$ เทียบกับความคลาดเคลื่อนของเอนโทรปี
- **ชิ้นงาน** กราฟความสัมพันธ์ระหว่างความคลาดเคลื่อนเอนโทรปีกับอัตราการกู้กุญแจสำเร็จ, รหัสโจมตี
- **ระดับความยาก** ระดับสูง
- **ผลลัพธ์ที่คาดหมาย** พบว่าความคลาดเคลื่อนเอนโทรปีเพียง 2 บิตต่อตัวอย่างเพียงพอต่อการกู้กุญแจได้เกือบทั้งหมด

**เส้นทางที่ 4: การวัดปริภูมิกุญแจจริง (Real Key Space Measurement)**

- **โจทย์วิจัย** ปริภูมิเมล็ดกุญแจจริงของระบบคือเท่าใด และจำนวนกุญแจสมมูลที่แตกต่างกันเป็นเท่าใด
- **วิธีทำ** แจกแจงเมล็ดกุญแจแบบข้อความ (Text Seed) จากพจนานุกรมขนาดมาตรฐาน นับจำนวนเมล็ดที่ให้ตาราง $\sigma_k$ แตกต่างกัน และวัดการกระจายตัวของผลลัพธ์
- **ชิ้นงาน** ตารางเปรียบเทียบระหว่างขนาดที่อ้าง (ประมาณ $8.57 \times 10^{506}$) กับขนาดจริง
- **ระดับความยาก** ระดับกลาง
- **ผลลัพธ์ที่คาดหมาย** พบว่ามีเมล็ดที่ให้ผลซ้ำกันจำนวนมาก และปริภูมิจริงเล็กกว่าที่อ้างหลายร้อยอันดับขนาด

**เส้นทางที่ 5: การซ่อมระบบให้ปลอดภัย (Constructive Redesign)**

- **โจทย์วิจัย** ต้องแก้ไขระบบอย่างไรจึงจะต้านการโจมตีทั้งสี่คลาสได้ โดยคงความคิดริเริ่มเรื่องรหัสคอลลัทซ์ไว้
- **วิธีทำ** เพิ่มนอนซ์ต่อการเข้ารหัสหนึ่งครั้ง เพิ่มการเชื่อมโยงที่ขึ้นกับข้อความต้นฉบับ (Plaintext-Dependent Chaining) เปลี่ยนจากรหัสแทนที่เป็นการดำเนินการระดับบิตที่พึ่งพาความลับที่ต่อเนื่อง และเพิ่มรหัสยืนยันความถูกต้อง (MAC) เปรียบเทียบกับ ChaCha20-Poly1305 ในฐานะบรรทัดฐาน
- **ชิ้นงาน** ข้อเสนอการออกแบบใหม่พร้อมการพิสูจน์ความปลอดภัยเชิงรูปแบบอย่างง่าย การทดลองโจมตีซ้ำที่ล้มเหลว
- **ระดับความยาก** ระดับสูงมาก (เหมาะกับเล่มจบห้าบท)
- **ผลลัพธ์ที่คาดหมาย** ระบบที่ผ่านการพิสูจน์ IND-CPA และทนต่อการโจมตีทุกคลาสที่เคยทำลายต้นฉบับ
- **ข้อควรระวังสำหรับผู้ประเมิน** การผสมค่าแฮชของภาพต้นฉบับ (เช่น SHA-256) เข้ากับเมล็ดกุญแจ (Plaintext-Aware Key Generation) เป็นแนวทางที่ทำให้กุญแจขึ้นกับข้อความต้นฉบับจริง แต่ **ไม่ใช่การพิสูจน์ความปลอดภัย** และยังไม่แก้ปัญหาการเชื่อมโยงกุญแจซ้ำในระดับที่เพียงพอ ต้องประเมินด้วยการวิเคราะห์ไม่ใช่ด้วยสัญชาตญาณ

**เส้นทางที่ 6: ตัวสร้างเลขสุ่มเทียมจากคอลลัทซ์ (Collatz PRNG Quality)**

- **โจทย์วิจัย** วงโคจรคอลลัทซ์ภายใต้ความแม่นยำจำกัดมีคุณสมบัติเพียงพอต่อการเป็นตัวสร้างเลขสุ่มเทียมหรือไม่
- **วิธีทำ** วัดความยาวรอบ (Cycle Length) ของวงโคจรภายใต้การล้น 32 และ 64 บิต รันชุดทดสอบ NIST SP 800-22 และ PractRand ตามแนวทางของ Dziala (2023) ซึ่งอยู่ในคู่มือ `guide-02-dziala-prng.md`
- **ชิ้นงาน** ตารางผลทดสอบ NIST, กราฟความยาวรอบ, การวิเคราะห์การเสื่อมสภาพเชิงพลวัต
- **ระดับความยาก** ระดับกลางถึงสูง
- **ผลลัพธ์ที่คาดหมาย** พบว่าวงโคจรล้นจะเข้าวงรอบสั้น และการทดสอบ NIST บางรายการล้มเหลว

**เส้นทางที่ 7: วิพากษ์ตัวชี้วัดความปลอดภัย (Metric Critique)**

- **โจทย์วิจัย** ตัวชี้วัด NPCR, UACI, เอนโทรปี แยกแยะระบบที่ปลอดภัยออกจากระบบที่พังแล้วได้จริงหรือไม่
- **วิธีทำ** สร้างระบบที่รู้ว่าพังจำนวนสามถึงห้าระบบ (เอกลักษณ์บวกมาสก์คงที่, การ XOR ด้วยคีย์ซ้ำ, การสลับเฉพาะตำแหน่ง) แล้วรายงานตัวชี้วัดทั้งหมดเทียบกับระบบของ Ballesteros และระบบของ ChaCha20
- **ชิ้นงาน** ตารางที่แสดงว่าระบบที่พังแล้วยังได้ตัวชี้วัดครบตามเกณฑ์
- **ระดับความยาก** ระดับต่ำถึงกลาง (เหมาะเป็นโครงงานนิสิตที่พื้นฐานไม่แข็ง)
- **ผลลัพธ์ที่คาดหมาย** ข้อสรุปเชิงระเบียบวิธีที่ชัดเจนและตีพิมพ์ได้ในเชิงการศึกษา

**เส้นทางที่ 8: การพิสูจน์ขอบเขตความยาวรหัสคอลลัทซ์ (Code Length Bounds)**

- **โจทย์วิจัย** ความยาวรหัสคอลลัทซ์เฉลี่ยเป็นเท่าใด และมีขอบเขตเชิงเส้นกำกับอย่างไร
- **วิธีทำ** พิสูจน์ขอบเขตบนและล่างของความยาวรหัสด้วยทฤษฎีจำนวน และตรวจสอบกับผลของ Terras และ Lagarias เรื่องเวลาหยุดรวม (Total Stopping Time) ยืนยันด้วยการคำนวณแบบครบถ้วนสำหรับช่วงที่กว้างขึ้น
- **ชิ้นงาน** ทฤษฎีบทขอบเขตพร้อมการพิสูจน์ และตารางการตรวจสอบเชิงตัวเลข
- **ระดับความยาก** ระดับสูง (เหมาะกับนิสิตสายทฤษฎี)
- **ผลลัพธ์ที่คาดหมาย** ได้ผลลัพธ์ทางคณิตศาสตร์ที่แท้จริง ไม่ใช่เพียงการทดลอง

**เส้นทางที่ 9: การโจมตีระบบของ Al-Hyari และคณะ 2024 (Second Target)**

- **โจทย์วิจัย** ระบบที่มีการสลับแถวและคอลัมน์แบบพึ่งกุญแจเพียงอย่างเดียวถูกทำลายด้วยจำนวนภาพที่รู้จำนวนเท่าใด
- **วิธีทำ** ใช้คลาสการโจมตีของ Solak และคณะ (2010) และ Li และ Lo (2011) กู้กระแสกุญแจจากการ XOR กู้การเรียงสับเปลี่ยนจากการเปรียบเทียบภาพหลายคู่ และวัดปริภูมิกุญแจจริงของเลข 15 หลัก
- **ชิ้นงาน** สคริปต์โจมตี, ตารางเวลาที่ใช้, การวิเคราะห์ความคลาดเคลื่อนจากที่เปเปอร์อ้าง $2^{97}$
- **ระดับความยาก** ระดับสูง
- **ผลลัพธ์ที่คาดหมาย** กู้กระแสกุญแจได้จากภาพที่รู้เพียงหนึ่งภาพ และแสดงว่าปริภูมิกุญแจจริงประมาณ $2^{49.8}$

**เส้นทางที่ 10: การศึกษาแบบทบทวนซ้ำ (Replication and Meta-Science)**

- **โจทย์วิจัย** ผลลัพธ์ของเปเปอร์ 2018 ทำซ้ำได้หรือไม่ และความไม่ชัดเจนของคำบรรยายมีผลต่อการทำซ้ำอย่างไร
- **วิธีทำ** ทำตามคำบรรยายอย่างเคร่งครัด บันทึกจุดที่ต้องตัดสินใจเองทุกจุด แล้วสร้างระบบที่แตกต่างกันสองถึงสามเวอร์ชันจากคำบรรยายเดียวกัน เปรียบเทียบผลลัพธ์
- **ชิ้นงาน** รายงานความไม่ชัดเจนของคำบรรยาย (Specification Gap Report) และผลกระทบเชิงปริมาณ
- **ระดับความยาก** ระดับกลาง
- **ผลลัพธ์ที่คาดหมาย** พบว่าผลลัพธ์ระดับภาพแตกต่างกันอย่างมีนัยสำคัญระหว่างการตีความที่ต่างกัน

### 8.3 รูปแบบโครงงานที่แนะนำ (Recommended Project Shape)

ผู้วิจารณ์แนะนำโครงสร้างสามระยะที่ใช้ได้กับทุกเส้นทาง

1. **ระยะทำซ้ำ (Reproduce)** หนึ่งเดือนแรก นิสิตสร้างระบบเดิมให้ทำงานได้ก่อน ยังไม่ต้องสนใจว่าปลอดภัยหรือไม่ เป้าหมายคือเข้าใจกลไกอย่างถ่องแท้ และบันทึกข้อบกพร่องในการทำซ้ำ
2. **ระยะทำลาย (Break)** หนึ่งเดือนที่สอง นิสิตออกแบบและรันการโจมตีอย่างน้อยหนึ่งคลาส และต้องรายงาน **เวลา จำนวนข้อมูลที่ใช้ และความสำเร็จเป็นตัวเลข** ไม่ใช่รายงานความรู้สึก
3. **ระยะซ่อมหรือขยาย (Fix or Extend)** สองเดือนสุดท้าย เป็นการเสนอการแก้ไขพร้อมการโจมตีซ้ำที่ล้มเหลว หรือขยายผลเชิงทฤษฎีที่พิสูจน์ได้

โครงสร้างนี้รับประกันว่านิสิตมีความรู้ขั้นต่ำที่แท้จริง แม้ระยะที่สองจะไม่สำเร็จ

## 9. แผนประเมินผลแบบยึดการโจมตีเป็นหลัก (Attack-First Assessment Rubric)

ข้อเสนอให้เปลี่ยนเกณฑ์การประเมินจาก "จำนวนตัวชี้วัดที่ผ่าน" เป็น "คุณภาพของการวิเคราะห์เชิงปฏิปักษ์"

| มิติการประเมิน | น้ำหนัก | คำอธิบาย | หลักฐานที่ต้องมี |
|:---|:---:|:---|:---|
| การระบุช่องโหว่ | ร้อยละ 25 | ระบุช่องโหว่ได้อย่างน้อยหนึ่งคลาส พร้อมเหตุผลเชิงทฤษฎี | แบบจำลองผู้โจมตีที่ชัดเจน |
| การลงมือโจมตีจริง | ร้อยละ 30 | การโจมตีรันได้และได้ผลตามที่คาด หรืออธิบายความล้มเหลวได้ชัดเจน | สคริปต์ที่รันได้ ผลการวัด เวลา |
| ความเข้าใจเชิงรหัสลับ | ร้อยละ 20 | อธิบายได้ว่าทำไมตัวชี้วัดมาตรฐานไม่ใช่หลักฐานความปลอดภัย | ข้อโต้แย้งที่อ้างงานตีพิมพ์ |
| การนำเสนอข้อบกพร่องของเปเปอร์ | ร้อยละ 15 | ระบุข้อผิดพลาดทางคณิตศาสตร์ของเปเปอร์ได้ถูกต้อง | การอ้างอิงบรรทัดหรือสมการ |
| ข้อเสนอการแก้ไข | ร้อยละ 10 | เสนอการแก้ไขที่สมเหตุสมผลและวิพากษ์วิจารณ์ตนเองได้ | ข้อจำกัดของการแก้ไขของตนเอง |

**เกณฑ์ผ่านขั้นต่ำ (Minimum Bar)** นิสิตต้องแสดงอย่างน้อยหนึ่งหลักฐานต่อไปนี้

- การโจมตีที่สำเร็จพร้อมตัวเลขผลลัพธ์
- การหักล้างตัวเลขที่เปเปอร์อ้างด้วยการคำนวณซ้ำ
- การอธิบายข้อบกพร่องเชิงระเบียบวิธีของเปเปอร์พร้อมหลักฐาน

**ห้ามผ่าน** รายงานที่สรุปว่าปลอดภัยโดยอาศัยเฉพาะตารางตัวชี้วัดที่รันซ้ำโดยไม่มีการวิเคราะห์เชิงปฏิปักษ์

## 10. ข้อเสนอแนะเชิงปฏิบัติสำหรับอาจารย์ (Actionable Recommendations)

### 10.1 ปรับกรอบหัวข้อสัมมนา

เปลี่ยนชื่อหัวข้อจาก

> ระบบเข้ารหัสภาพด้วยความโกลาหลของคอลลัทซ์

เป็น

> การวิเคราะห์เชิงรหัสลับและการซ่อมแซมระบบเข้ารหัสภาพด้วยสมมติฐานคอลลัทซ์ (Cryptanalysis and Redesign of Collatz-Based Image Ciphers)

กรอบใหม่นี้ **ยังใช้ภาพเป็นผลลัพธ์ให้เห็นผลด้วยตาเปล่า** ยังได้เรียน Python และ NumPy แต่ให้คุณค่าทางวิชาการสูงกว่ามาก และสามารถตีพิมพ์ได้จริงในที่ประชุมระดับนักศึกษา

### 10.2 แก้ไขเอกสารจัดอันดับภายใน

เอกสาร `guides/PAPER_BENCHMARK_RANKING.md` ต้องปรับอย่างน้อยสี่จุด

1. เปลี่ยนคำอธิบายความเสี่ยงของหัวข้อจาก "ต่ำมาก (Safe Zone)" เป็น "ปานกลางถึงสูง" พร้อมเหตุผลว่าความปลอดภัยของระบบถูกหักล้างด้วยการโจมตีที่รู้ข้อความต้นฉบับ
2. ลบหรือแก้ข้ออ้างเรื่อง "ตัวชี้วัดตามมาตรฐานสากล" ให้ระบุชัดว่าตัวชี้วัดเหล่านี้เป็นสัญญาณจำเป็น ไม่ใช่หลักฐานความปลอดภัย
3. เพิ่มหมายเหตุว่าระบบต้นฉบับมีช่องโหว่ระดับทำลายทั้งหมดต่อการโจมตีแบบเลือกและแบบรู้ข้อความต้นฉบับ
4. เพิ่มคอลัมน์ "สถานะความปลอดภัยที่แท้จริง" แยกจาก "ความพร้อมด้านเครื่องมือ"

### 10.3 แก้ไขรหัสตั้งต้นในคู่มือ guide-04

1. ระบุให้ชัดว่าโค้ดตัวอย่างเป็น **ระบบใหม่ที่ได้แรงบันดาลใจจากเปเปอร์** ไม่ใช่ระบบของ Ballesteros 2018
2. เพิ่มคอมเมนต์เตือนในโค้ดว่ากระบวนการนี้ **ไม่ปลอดภัยต่อการโจมตีแบบรู้ข้อความต้นฉบับ** และใช้เพื่อการเรียนรู้เท่านั้น
3. แก้ไขการเรียก `np.argsort` ให้ใช้ `kind='stable'` เพื่อการทำซ้ำที่แน่นอน
4. เพิ่มการวิเคราะห์ความยาวรอบของวงโคจรคอลลัทซ์ภายใต้การล้น 64 บิต
5. เพิ่มฟังก์ชันนอนซ์ (Nonce) อย่างน้อยในรูปของตัวนับ เพื่อให้นิสิตเห็นความแตกต่างระหว่างระบบมีและไม่มีนอนซ์
6. เพิ่มสคริปต์โจมตีแบบเลือกข้อความต้นฉบับในชุดส่งมอบ

### 10.4 เกณฑ์ผ่านขั้นต่ำของสัมมนา

กำหนดว่ารายงานสัมมนาที่ใช้เปเปอร์นี้ **ต้องมีหัวข้อการวิเคราะห์เชิงปฏิปักษ์อย่างน้อยหนึ่งบท** และห้ามใช้ประโยค "ระบบนี้ปลอดภัย" โดยไม่มีแบบจำลองผู้โจมตีประกอบ

### 10.5 แหล่งอ่านบังคับก่อนเริ่มเขียนโค้ด

ให้นิสิตอ่านงานสี่ชิ้นนี้ก่อนเริ่ม เพื่อสร้างความเข้าใจเชิงปฏิปักษ์ที่ถูกต้อง

1. Özkaynak (2018) เรื่องรายการตรวจสอบความปลอดภัยของระบบความโกลาหลในงานเข้ารหัสภาพ ซึ่งเป็นรายการตรวจสอบมาตรฐานที่นิสิตควรใช้เป็นแผนที่การทดสอบ
2. Li และ Lo (2011) เรื่องการวิเคราะห์เชิงปริมาณที่เหมาะสมที่สุดสำหรับรหัสที่มีเฉพาะการสลับตำแหน่ง เพื่อให้เห็นว่าจำนวนภาพที่ต้องใช้ในการโจมตีมีขอบเขตชัดเจน
3. Li, Lin, Feng, Lü และ Hao (2018) เรื่องการทำลายระบบเข้ารหัสภาพที่อ้างความปลอดภัยจากค่าเอนโทรปี ซึ่งเป็นกรณีศึกษาที่ตรงกับหัวข้อสัมมนามากที่สุด
4. Solak, Çokal, Yıldız และ Biyikoğlu (2010) และ Xie, Li, Yu และ Lü (2017) เรื่องการทำลายระบบของ Fridrich ซึ่งเป็นบรรพบุรุษของระบบสับเปลี่ยนและแพร่กระจายทั้งหมด

## 11. ตารางสรุปข้อค้นพบตามระดับความรุนแรง (Severity-Ranked Findings)

นิยามระดับความรุนแรงของเอกสารนี้

- **ระดับ I (รุนแรงมาก)** ข้ออ้างหลักของเปเปอร์เป็นเท็จ หรือมีช่องโหว่ที่ทำลายระบบทั้งหมด
- **ระดับ II (รุนแรง)** ข้อผิดพลาดทางคณิตศาสตร์หรือทางระเบียบวิธีที่มีนัยสำคัญ
- **ระดับ III (ควรแก้ไข)** ความไม่ชัดเจน ความไม่สอดคล้อง หรือการนำเสนอที่ทำให้เข้าใจผิด
- **ระดับ IV (ข้อสังเกต)** จุดที่ควรปรับปรุงแต่ไม่กระทบข้อสรุปหลัก

## ภาคผนวก ก: ชุดคำสั่งตรวจสอบซ้ำ (Reproducible Verification Snippets)

โค้ดต่อไปนี้ใช้ยืนยันข้อเท็จจริงเชิงตัวเลขที่อ้างในเอกสารนี้ทั้งหมด นิสิตสามารถรันด้วย Python มาตรฐาน (ไม่ต้องใช้ไลบรารีภายนอก)

```python
import math
from math import log2, factorial

def traj(n):
    seq = [n]
    while n != 1:
        n = n // 2 if n % 2 == 0 else 3 * n + 1
        seq.append(n)
    return seq

rows = [(n, len(traj(n)) - 1, len(traj(n))) for n in range(1, 257)]
steps = [r[1] for r in rows]
terms = [r[2] for r in rows]

print("รอบเฉลี่ย =", sum(steps) / len(steps))
print("รอบสูงสุด =", max(steps))
print("ความยาวรหัสเฉลี่ย =", sum(t + 2 for t in terms) / 256)
print("ลอการิทึมฐานสองของ 256! =", log2(factorial(256)))
print("ปริภูมิข้อความภาพ 512x512 = 2^", 512 * 512 * 8)

L = 512 * 512
mean_code = sum(t + 2 for t in terms) / 256
print("อัตราขยาย =", round(mean_code / 8, 2))
```

ผลลัพธ์ที่คาดหมาย รอบเฉลี่ย 44.98, รอบสูงสุด 127, ความยาวรหัสเฉลี่ย 47.98, $\log_2(256!) = 1684.0$ และอัตราขยาย 6.00
